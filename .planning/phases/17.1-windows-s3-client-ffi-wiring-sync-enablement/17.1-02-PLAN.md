<objective>
Bind the two new exports in `DS3Native.cs`, build the `DS3DriveS3Client : IDisposable` facade that owns the minted handle and re-homes the six S3 methods onto it, un-ignore `endpoint_gateway` on `DS3AccountInfo`, and remove the Wave-1 stopgap where `DS3Session` S3 methods pass the session handle into S3 exports (the AVE bug).

Purpose: Criterion #1 (C# owns/disposes the handle) and Criterion #2 plumbing (endpoint field surfaced). This is the structural fix for the `AccessViolationException`: the S3 ops now route through a real `DS3S3Client` handle instead of `DS3Session`'s `EnsureHandle()`.

Output: One new facade class, two P/Invoke bindings, one DTO field, and the deletion of the S3-method stopgap from `DS3Session`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| C# (managed) → Rust C-ABI | S3 ops cross the boundary with the DS3DriveS3Client handle; secret crosses once at Create |
| DS3DriveS3Client.Dispose → process | Single-shot free of the raw handle; concurrent in-flight calls must be ordered out by the host (Plan 03) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-17.1-05 | Tampering / DoS | Wrong-type handle deref (the original AVE) | mitigate | DS3DriveS3Client owns a real DS3S3Client handle; DS3Session S3 methods removed (D-02) — the session handle can no longer reach an S3 export |
| T-17.1-06 | Tampering / DoS | Double-free of the S3 handle | mitigate | `Interlocked.Exchange(ref _handle, IntPtr.Zero)` makes Dispose single-shot (copied from DS3Session.cs:340) |

| T-17.1-08 | Information Disclosure | Secret key leaking via exception message | mitigate | DS3ExceptionFactory.From logs the numeric code only, never raw message (T-17-05-03); the facade never logs the secret arg |
