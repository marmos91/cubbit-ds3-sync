# Phase 17.1 Plan 02: Windows S3-Client FFI Wiring (Wave 2) Summary

**A handle-owning `DS3DriveS3Client : IDisposable` facade that mints/frees a real `DS3S3Client` handle and re-homes the six S3 ops off `DS3Session` — the structural fix for the wizard's `AccessViolationException` — plus the two P/Invoke bindings and the `EndpointGateway` DTO field that unblock Plan 03.**

## Accomplishments
- Added the two `[DllImport("ds3_ffi")]` bindings (`ds3_s3_client_new` mint + `ds3_s3_client_destroy` drop) at the head of the S3 section in `DS3Native.cs`, and bumped the header export-count guard note to 39 (grep `EntryPoint = "ds3_s3_client_` returns 2).
- Un-ignored `endpoint_gateway` on `DS3AccountInfo` as `EndpointGateway` (mapped to the `endpoint_gateway` wire key per `core/ds3-models/src/account.rs`), surfacing the S3 endpoint Plan 03 needs to build the per-drive client.
- Created `DS3DriveS3Client : IDisposable` owning a single `IntPtr _handle`: `Create(endpoint, accessKey, secretKey, region?)` mints via `ds3_s3_client_new`; `Dispose()` frees once via `Interlocked.Exchange` + `ds3_s3_client_destroy`; `EnsureHandle()` short-circuits a gone handle to a managed `DS3AuthenticationException(LoggedOut, 1005)` (never an AVE).
- Re-homed the seven S3 methods (`ListBuckets`/`ListObjects`/`HeadObject`/`DownloadObject`/`UploadObject`/`DeleteObject`/`CopyObject`) plus the folder-marker pair (`ProbeFolderExists`/`CreateFolderMarker`) onto the facade — bodies copied verbatim, swapping the session-handle `EnsureHandle()` for the facade's own handle guard.
- Deleted the S3 methods and the Wave-1 stopgap comment from `DS3Session` (now auth/session-only, D-02); documented the ~40-thread no-mutex concurrency contract (Pitfall 3 / T-17.1-07) on the facade.
- `dotnet build DS3Drive.Core` exits 0 (0 warnings); the managed-only DS3DriveS3Client lifecycle tests now exercise the real facade (no longer no-op) and pass; full 145/145 non-integration suite green; `dotnet format --verify-no-changes` clean.

## Decisions Made
- Copied the `M` marshalling helpers + `Check`/`Parse<T>` into `DS3DriveS3Client` verbatim rather than extracting a shared helper. PATTERNS §"Shared Patterns" explicitly sanctions either; copying keeps the plan-02 diff entirely additive on the new file with no cross-cutting refactor of `DS3Session`.
- Inserted `EndpointGateway` as the 3rd positional record parameter (ahead of the `[JsonIgnore]`'d `Email`/`DisplayName`). This is positional-API-breaking in principle, but a repo-wide grep for `new DS3AccountInfo(` returned zero call sites — every construction is via `JsonSerializer.Deserialize`, which is name-based — so no caller breaks.
- `Create`'s `region` parameter is optional (`string? region = null`); null/empty marshals to `null,0`, which the Rust `ffi_opt_str` reads as `None` and defaults to `us-east-1` — the macOS-parity behavior locked in Plan 01. No C#-side sentinel.
- Left `DS3Session.M.WrapProgress` in place though it is now dead (its only callers were the removed S3 methods). The build reports 0 warnings, so it is not a CI hazard, and excising it would churn the marshalling-helper region for no behavioral gain.
