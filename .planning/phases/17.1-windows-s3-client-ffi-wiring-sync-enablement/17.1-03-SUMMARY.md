# Phase 17.1 Plan 03: Windows S3-Client FFI Wiring (Wave 3) Summary

**Wires the `DS3DriveS3Client` facade into runtime: a per-drive `DriveS3SessionAccess` adapter routes the six cfapi sync ops through a credential-built S3 handle, the sync host builds/rebuilds/disposes that handle, the wizard browse re-points off the session onto a per-project client (crash-free with D-06 inline error + Retry), and the live integration round-trip is filled in — making WIN-03..WIN-08 functional at runtime.**

## Accomplishments
- Added `DriveS3SessionAccess` — a `sealed class : IDS3SessionAccess` that routes `ListObjects`/`DownloadObject`/`UploadObject`/`DeleteObject`/`CopyObject` + `AccountId` through ONE injected `DS3DriveS3Client` (shape copied from `AuthenticationService.cs:216-237`, swapping `EnsureSession()` for the per-drive handle). The 6-op seam (`IDS3SessionAccess`) is unchanged.
- Introduced `IDriveS3CredentialProvider` (Sync) + `DriveS3Credentials` record, implemented by App-layer `DriveS3CredentialProvider`: resolves per-drive creds from the API-key flow (reconciled `AccessKey`/`SecretKey` + `IDS3SessionGateway.EndpointGateway`), reconstructing the IAM user from the anchor exactly like `RepairCredentialsAsync`. Guards the empty-endpoint pitfall (T-17.1-13).
- Rewired `SyncHostedService.StartDriveAsync` to build `DS3DriveS3Client.Create(endpoint, access, secret)` from the resolved creds (outside the lock), wrap it in a `DriveS3SessionAccess`, and pass THAT (not the shared `_session`) into `UploadQueue`/`CfApiProvider`/`SyncEngine`. The `ActiveDrive` record now holds the `DS3DriveS3Client` + the `DriveS3Credentials` it was built from.
- Implemented rebuild-on-change (Pitfall 5): a later `StartDriveAsync` for an already-active drive compares the freshly-resolved creds against the captured ones (record equality) and Dispose+Create's the client when they differ. `StopActiveAsync` disposes the S3 client LAST — after `Engine.StopAsync` + `Provider.DisconnectAsync` — so no in-flight op races the free (Pitfall 4 / T-17.1-11).
- Re-pointed `DS3SdkService.GetBucketsAsync`/`ListChildPrefixesAsync` through a per-project `DS3DriveS3Client` (cached under a `SemaphoreSlim`, reconcile outside the lock); the session handle is no longer dereferenced for S3 (the AVE root cause). `DS3SdkService` is now `IDisposable` (disposes the cached browse clients).
- Wired the Bucket-step D-06 Retry: `BucketSelectionPage.xaml`'s error `InfoBar` gained an `ActionButton` bound to `LoadBucketsCommand` and its `Message` now binds to the mapped `CreationError` copy. No `AccessViolationException` catch added (Pitfall 1 — corrupted-state exception, never delivered to `catch`).
- Updated DI in `App.xaml.cs`: removed the `IDS3SessionAccess` → shared-`AuthenticationService` registration (the host builds the per-drive adapter) and registered `IDriveS3CredentialProvider`.
- Filled in the live-credential integration bodies (`Create_FromReconciledApiKey_Lists`, `RoundTrip_ListHeadUploadDownloadDeleteCopy`): authenticate → forge IAM token → create throwaway API key → `DS3DriveS3Client.Create` → exercise list/head/upload/download/delete/copy through the NEW handle and assert the round-trip, with cleanup of both the scratch keys and the API key.
- Full solution builds 0 warnings / 0 errors; 145/145 non-integration tests pass; `dotnet format --verify-no-changes` clean across App/ViewModels/Sync/Tests.

## Decisions Made
- **Credential resolution is a new seam, not a widened one.** `IDS3SessionAccess` (the 6-op cfapi seam) carries no drive context by design; rather than widen it, a separate `IDriveS3CredentialProvider` (Sync-defined, App-implemented) resolves the per-drive creds and the host binds the drive scope into the `DriveS3SessionAccess`. Keeps the boundary discipline identical to `IDriveLifecycleSource`.
- **Rebuild detection by record equality.** The host captures the `DriveS3Credentials` used to build each drive's client; a later `StartDriveAsync` recomputes them and `!=` on the record (endpoint + access + secret) is the change signal — the minimal, allocation-free `reloadDriveCredentials` parity for 17.1.
- **Project-name proxy = bucket for the host's reconcile.** `DriveS3CredentialProvider` passes `anchor.Bucket` as the `projectName` to `LoadOrCreateApiKeyAsync`, byte-aligned with `DriveManagementService.RepairCredentialsAsync`, so the host's deterministic key name matches the one already on disk (the SDK short-circuits to the cached local key).
- **Integration test reconciles a throwaway key directly via `DS3Session`** (forge IAM token → create key → delete in `finally`) rather than spinning the full DI `DS3SdkService` stack — keeps the live test self-contained and leaves no residue. It exercises the criterion-#2 invariant (creds from the API-key flow, not the session token) and the criterion-#4 full round-trip.
