# Phase 17.1: Windows S3-Client FFI Wiring + Sync Enablement - Discussion Log

> **Audit trail only.** Do not use as input to planning, research, or execution agents.
> Decisions are captured in CONTEXT.md — this log preserves the alternatives considered.

**Date:** 2026-06-01
**Phase:** 17.1-windows-s3-client-ffi-wiring-sync-enablement
**Areas discussed:** S3 client ownership/lifecycle, Credential derivation timing, Wizard S3 error UX, Verification approach

**Cross-cutting user directive:** "Follow same UX of macOS" — all decisions were taken to mirror the macOS `DS3Client` S3 behavior.

---

## S3 Client Ownership & Lifecycle

| Option | Description | Selected |
|--------|-------------|----------|
| Per-drive facade, cached | New `DS3DriveS3Client` owns one `DS3S3Client` handle per drive, disposed with the sync host; `DS3Session` stays auth-only. Mirrors macOS `driveS3Client`. | ✓ |
| Extend DS3Session | `DS3Session` mints + caches S3 client handles (one class for session + S3). | |
| Per-operation client | Create + destroy a client around each S3 call. | |

**User's choice:** Per-drive facade, cached (Recommended)
**Notes:** Sets up future multi-drive (POL-04); keeps auth and S3 lifetimes decoupled.

---

## Credential Derivation & Timing

| Option | Description | Selected |
|--------|-------------|----------|
| Reconcile at wizard, persist, build at startup | Wizard reconciles the API key; persist per-drive creds (ConfigStore); sync host builds the client at startup, rebuilds on change (macOS `reloadDriveCredentials`). | ✓ |
| Lazy at client-build time | Derive creds via a `loadOrCreateDS3APIKeys` equivalent only when first needed; no separate persist. | |

**User's choice:** Reconcile at wizard, persist, build at startup (Recommended)
**Notes:** DPAPI encryption-at-rest deferred to Phase 18 (POL-03); ConfigStore used for now.

---

## Wizard S3 Error UX

| Option | Description | Selected |
|--------|-------------|----------|
| Inline error + Retry on the step | Stay on the Bucket step, show a friendly message mapped from the typed `DS3S3Exception`, with Retry. | ✓ |
| Route back to project step | Send the user back to project/API-key selection on failure. | |
| Tray toast + stay | Surface the error as a Windows tray toast. | |

**User's choice:** Inline error + Retry on the step (Recommended)
**Notes:** Replaces the prior hard crash (`AccessViolationException`) at this step.

---

## Verification Approach

| Option | Description | Selected |
|--------|-------------|----------|
| Automated integration test + manual ARM64 smoke | Gated C# integration test over all six S3 ops through the new handle, plus a manual ARM64 smoke checklist for the full wizard→round-trip. | ✓ |
| Manual ARM64 smoke only | Documented manual checklist, no new automated test. | |
| Automated integration test only | Rely on the gated integration test; skip a manual checklist. | |

**User's choice:** Automated integration test + manual ARM64 smoke (Recommended)
**Notes:** Integration test gated on Cubbit secrets like the existing "C# P/Invoke Tests (Windows)" CI job.
