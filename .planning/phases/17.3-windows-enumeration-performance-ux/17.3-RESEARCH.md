# Phase 17.3: Windows Enumeration Performance & UX - Research

**Gathered:** 2026-07-07
**Method:** Read-only code recon of `windows/` (C# cfapi sync engine) + `core/` (Rust FFI) + `apple/DS3DriveProvider` (macOS parity reference). All paths relative to repo root. File:line references are anchors for planning — re-verify before editing (code may drift).

This document is the evidence base for `17.3-CONTEXT.md`. It maps the **current** enumeration + placeholder pipeline and pinpoints the gaps behind 17.3's three success criteria.

## Area 1 — cfapi enumeration → placeholder creation

Two entry paths create placeholders in Explorer:

**A. Eager root population (once, at drive registration)**
- `windows/DS3Drive.Sync/CfApi/CfApiProvider.cs:77` `RegisterAsync` → registers sync root, connects callback table, spawns background `PopulatePlaceholdersAsync` (`:127`).
- `:133` → `PlaceholderMaterializer.MaterializeAsync`.
- `windows/DS3Drive.Sync/CfApi/PlaceholderMaterializer.cs:217` `MaterializeAsync` → `ListLevel` (root prefix) → `BuildLevel` → one `CfCreatePlaceholders` batch (`CreatePlaceholders`, `:259`). **Root-level only, no recursion** — subdirs populate lazily.
- `CfApiProvider.cs:105-108`: FETCH_PLACEHOLDERS "was observed NOT to fire for the sync-root directory," so eager population is the reliable root path.

**B. On-demand child population (per directory open)**
- `windows/DS3Drive.Sync/CfApi/FetchPlaceholdersHandler.cs:64` `OnFetchPlaceholders` (CF_CALLBACK_TYPE_FETCH_PLACEHOLDERS) → `HandleAsync` (`:73`).
- `HandleAsync` re-prefixes path (`:79-80`), `PlaceholderMaterializer.ListLevel` (`:85`), `BuildLevel` (`:91`), one `TransferPlaceholders` batch (`:95`/`:132`) with `CF_OPERATION_TRANSFER_PLACEHOLDERS_FLAG_DISABLE_ON_DEMAND_POPULATION` (`:153`) — marks dir fully populated. Mirrors each child into the index (`:107-110` `_store.UpsertAsync`).

**Listing core:** `PlaceholderMaterializer.ListLevel` (`PlaceholderMaterializer.cs:71-105`) is delimited (`"/"`); filters common-prefix folders, prefix-self marker, trailing-slash objects, `.ds3keep` (`IsInternalMarker`, `:34`), hidden `.trash`/`.thumbnails` (`IsHiddenSystemKey`, `:42`).

> **GAP (paging/UX):** `ListLevel` chases the continuation token to completion (`:76-102`), buffering the **entire level in memory** before a single `CfExecute(TRANSFER_PLACEHOLDERS)` / `CfCreatePlaceholders`. No incremental streaming as pages arrive — unlike macOS `finishEnumerating(upTo:)` (Area 6). At tens of thousands of children: one blocking buffer + one giant batch. → **Criterion 1 (D-02).**

- **Rust core:** `core/ds3-s3/src/list.rs:11` `list_objects(bucket, prefix, delimiter, max_keys, continuation_token)` → single `ListObjectsV2` page → `S3ListingResult { objects, common_prefixes, next_continuation_token, is_truncated }`. Default page `LIST_BATCH_SIZE = 2000` (`core/ds3-s3/src/client.rs:11`).
- **C ABI:** `core/ds3-ffi/src/c_exports.rs:508` `ds3_list_objects`; `max_keys` → `if max_keys > 0 { Some } else { None }` (`:531`) — `0` means default 2000.
- **C# P/Invoke:** `windows/DS3Drive.Core/Generated/DS3Native.cs:122` `ds3_list_objects` (13 args incl. `int max_keys`).
- **C# client:** `windows/DS3Drive.Core/DS3DriveS3Client.cs:98` `ListObjectsListing` — **hardcodes `max_keys = 0`** (`:107`); no caller override. Returns one page (`DS3ObjectListing { Objects, CommonPrefixes, NextContinuationToken, IsTruncated }`). `ListObjects` (`:91`) drops common prefixes.

> **NOTE:** pagination is fully plumbed at the FFI (continuation token round-trips); page size fixed at 2000, no C#-side override wired. → relevant to **D-05**.

## Area 3 — Paged vs all-at-once; idempotency; duplicate/ghost prevention

**Paging is inconsistent across the two consumers:**
- `PlaceholderMaterializer.ListLevel` **does** loop the token (`:76-102`) — all pages (buffered).
- **`SyncEngine.PollOnceAsync` does NOT page** — `windows/DS3Drive.Sync/SyncEngine/SyncEngine.cs:121` issues one `ListObjectsListing(bucket, prefix, "/", null)`, never consults `IsTruncated`/`NextContinuationToken`. **A prefix with >2000 direct children sees only page 1**; because the diff treats absent remote keys as deletions, everything past page 1 is computed `Deleted` and pruned.

> **GAP (critical correctness / data loss):** the single most important bug for "at scale." → **Criterion 2 (D-01).**

**Idempotency:**
- **DB rows:** composite `(drive_id, s3_key)` with `INSERT … ON CONFLICT(drive_id, s3_key) DO UPDATE` (`PlaceholderStore.cs:56-63`). Idempotent on **S3 key** (etag is a column, not part of the key).
- **On-disk placeholders:** `CfCreatePlaceholders` uses `CF_CREATE_FLAG_NONE`; tolerates `ERROR_ALREADY_EXISTS` (0x800700B7) as benign on re-registration (`PlaceholderMaterializer.cs:275-279`). `FileIdentity` = full S3 key UTF-16 (`:117`) — stable identity across re-enumeration.
- **Minor gap:** `FetchPlaceholdersHandler.TransferPlaceholders` does not diff against present placeholders — re-transfers the whole level each fire. `DISABLE_ON_DEMAND_POPULATION` normally makes it fire-once, but no explicit dedup guard if the platform re-requests.

**Ghost/deletion handling:** reconciled only via `SyncEngine.ApplyDeltaAsync` (`SyncEngine.cs:264-268`) → `PlaceholderStore.DeleteAsync` for `delta.Deleted`. Deletes the **DB row** but there is **no `CfDeletePlaceholders`/on-disk removal** in this path.

> **GAP (ghost):** on-disk ghost removal is unwired. → **Criterion 2 (D-03).**

## Area 4 — SQLite placeholder state + reconciliation

- **DB:** `windows/DS3Drive.Sync/Storage/SyncDatabase.cs` — `%LOCALAPPDATA%\Cubbit\DS3Drive\sync.db` (`:54`), WAL (`:100`), fresh connection per op (`AcquireConnectionAsync:111`), corrupt-store auto-delete+recreate (`OpenAsync:65`, "cache not user data").
- **Schema:** `windows/DS3Drive.Sync/Migrations/001_initial.sql` — `placeholders` PK `(drive_id, s3_key)`, cols `parent_key, etag, size, last_modified, is_folder, is_dirty, sync_status, last_seen_at`; indexes on `parent_key`, partial `is_dirty=1`, `sync_status`. Plus `002_singleton_state.sql`. Migrations via `SchemaMigrator.cs` (embedded-resource, versioned, transactional).
- **Store facade:** `PlaceholderStore.cs` — `PlaceholderRecord` (`:16`), `UpsertAsync`, `FindAsync`, `DeleteAsync`, `ListByPrefixAsync` (`:98`, NULL-vs-empty parent_key fix at `:109`), `MarkDirtyAsync`, `SetSyncStatusAsync`.
- **Reconciliation:**
  - Reference impl: `windows/DS3Drive.Sync/Storage/EnumerationDiff.cs:44` `Compute(local, remote)` — set arithmetic over `key→etag?` maps: `added = remote−local`, `modified = {k∈common | local[k]≠remote[k]}` (null-tolerant, ordinal), `deleted = local−remote`. Byte-for-byte port of Swift `EnumerationDiff`.
  - Production path: `SyncEngine.PollOnceAsync` (`:107`) builds `localMap` from `PlaceholderStore.ListByPrefixAsync`, `remoteMap` from the (single-page) listing incl. folder common-prefixes keyed null-etag (`:145-148`), then `ComputeDelta` (`:177`) prefers Rust `ds3_compute_diff` (`c_exports.rs:782`, via `DS3Session.ComputeDiff`), falls back to C# `EnumerationDiff` on FFI failure.
  - `ApplyDeltaAsync` (`:203`): NewOrModified → upsert reset to `cloud-only`; dirty-local + differing-remote-etag → conflict via `ConflictResolver`; Deleted → `DeleteAsync`.

> **Relevant to D-01/D-06:** the diff is sound; the defect is the *input* (single page) and the absence of a change cursor. The sync-anchor (D-06) hashes the **complete** `key→etag` map to skip re-diff when unchanged.

## Area 5 — Progress reporting + concurrency limits

- **Status model is binary, not quantitative:** `DriveStatus` enum (`windows/DS3Drive.Sync/SyncEngine/DriveStatus.cs`) = Idle/Syncing/Paused/Error. `DriveStatusChange` carries **only drive id + status, never file names or counts** (comment cites STRIDE **T-17-10-05**).
- **Broadcaster:** `windows/DS3Drive.Sync/SyncEngine/DriveStatusBroadcaster.cs` — counter-based `BeginOperation`/`EndOperation` (`:102`/`:109`), debounced idle, batch-error promotion, 30s counter-leak watchdog. Port of `NotificationsManager.swift`. Produces a **spinner ("Syncing"), not a percentage or "X of Y."** Every handler brackets work with Begin/End (Fetch/Poll/Upload).
- **cfapi state column:** `windows/DS3Drive.Sync/CfApi/StateUiSource.cs` — NOT a shell overlay handler; relies on placeholder in-sync/pin state (`CfSetInSyncState`) + sync-root status. Per-file state set on upload (`UploadQueue.SetInSyncStateSafe:130`) and fetch completion (`FetchDataHandler` sets `sync_status="synced":136`).
- **Tray:** `windows/DS3Drive.ViewModels/ViewModels/TrayDriveRowViewModel.cs` + `TrayViewModel.cs` — App forwards `DriveStatusBroadcaster.StatusChanged` → `ReportStatus` → row re-reads `GetStatus` (`:143`). `UpdateSpeed` transfer-speed hook exists but **no enumeration count/percent.**
- **Concurrency (bounded S3):**
  - Fetch/hydration: `SemaphoreSlim(20,20)` at `CfApiProvider.cs:40`, gated in `FetchDataHandler.StartDownloadAsync:207`; per-key download coalescing via `_downloads` `ConcurrentDictionary` (`FetchDataHandler.cs:62`).
  - Upload: `SemaphoreSlim(20,20)` + bounded channel (256) in `UploadQueue.cs:29-33`, gate at `DrainAsync:74`.

> **GAP (progress + bounded listing):** enumeration/listing has **no concurrency bound and no progress instrumentation**; the 20-permit semaphores cover only per-object fetch/upload. → **Criterion 3 (D-04 progress event; D-05 listing limiter).**

## Area 6 — macOS parity reference

- **Enumerator:** `apple/DS3DriveProvider/S3Enumerator.swift`.
  - `enumerateItems(for:startingAt:)` (`:92`) — **truly incremental/paged**: one `listS3Items(... continuationToken:)` per invocation (`:108`), streams that page to the observer via `observer.didEnumerate` + `observer.finishEnumerating(upTo: nextPage)` (`:123-126`); platform re-invokes with the next token. Mirrors into `MetadataStore.batchUpsertItems`; **prunes only when single-page** (`:149`, `isFirstPage && continuationToken == nil`) to avoid deleting keys that arrive later.
  - `enumerateChanges(for:from:)` (`:186`) — `listAllRemoteChildren()` (`:280`, buffers all pages) + `EnumerationDiff.compute` (`:217`), then `didUpdate`/`didDeleteItems`; computes new `NSFileProviderSyncAnchor` from a hash over `key→etag` (`:255`).
  - Sync anchor: `currentSyncAnchor` (`:63`) hashes cached children etags — macOS's change cursor. **Windows has no equivalent** (re-lists + full-diffs every poll).
- **Listing config:** `apple/DS3DriveProvider/S3Lib.swift:62` `listS3Items` → `maxKeys: DefaultSettings.S3.listBatchSize` = **2000** (`apple/DS3Lib/Sources/DS3Lib/Constants/DefaultSettings.swift:175`) — same as Windows `LIST_BATCH_SIZE`.
- **Concurrency parity:** Windows `SemaphoreSlim(20,20)` comments cite Apple `AsyncSemaphore(value: 20)`. macOS also has dedicated limiters (`BucketListingLimiter.swift`, `ThumbnailFetchLimiter.swift`); **Windows currently only has fetch + upload limiters** (no listing limiter → D-05).
