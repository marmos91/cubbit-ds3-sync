# Phase 17.3 · Plan 04 (Wave 3): Aggregate progress (D-04) + listing limiter (D-05) + sync anchor (D-06)

**Goal:** Enumeration/hydration progress is observable in the tray as aggregate, file-name-free numbers; listing concurrency is bounded to avoid S3 `SlowDown`; and an unchanged prefix short-circuits the full re-diff each poll.

**Depends on:** Waves 1–2.
**Decisions:** D-04, D-05, D-06.
**Criteria touched:** #3 (progress observable + bounded concurrency); #1/#2 efficiency.

## Context

- Status is a 4-value enum with counts deliberately suppressed (STRIDE **T-17-10-05**): `DriveStatus.cs`, `DriveStatusChange`, `DriveStatusBroadcaster.cs`. The broadcaster is a delicate high-fidelity port of `NotificationsManager.swift` — do **not** overload its status semantics.
- Listing has no concurrency bound; the `SemaphoreSlim(20,20)` limiters cover only fetch (`CfApiProvider.cs:40`) and upload (`UploadQueue.cs:29`). macOS has a dedicated `BucketListingLimiter`.
- No change cursor: the poll re-lists + full-diffs every 60s. macOS uses `NSFileProviderSyncAnchor` = hash over `key→etag` (`S3Enumerator.swift:63/255`).

## Tasks

1. **D-04 — aggregate progress signal (no file names).**
   - New record `DriveEnumerationProgress(Guid DriveId, long ItemsSeen, long? ItemsTotal, long BytesHydrated, EnumerationPhase Phase)` — opaque aggregates only, **never** a file name/key (T-17-10-05 preserved). `ItemsTotal` null = indeterminate (S3 gives no count up front; may stay null or be set once the final page lands).
   - Add a **separate** `event EventHandler<DriveEnumerationProgress>? ProgressChanged` to `DriveStatusBroadcaster` (additive; leaves `StatusChanged` and the counter/debounce algorithm untouched), or a sibling `EnumerationProgressReporter` injected alongside — choose the additive event to keep one broadcast seam per drive.
   - Emit from the streaming enumeration loop (increment `ItemsSeen` per page) and from `FetchDataHandler` on hydration (`BytesHydrated`, coalesced with the existing per-download progress plumbing, throttled like the Rust progress ≤1/100ms per STATE 17.1-UAT decision).
   - Wire to `TrayViewModel` / `TrayDriveRowViewModel` (`:143` `GetStatus`) for an "enumerating N items / hydrating X%" readout. `DriveStatusChange` stays unchanged.
2. **D-05 — bounded listing.** Add `BucketListingLimiter` (a `SemaphoreSlim`, parity with macOS) in `DS3Drive.Sync`; gate every `ListObjectsListing` page call (poll + streaming enumerator). Optionally expose a `maxKeys` override on `DS3DriveS3Client.ListObjectsListing` (currently hardcodes `0` at `DS3DriveS3Client.cs:107`) — only wire a smaller first-page size if Wave-2 timing shows it improves time-to-first-item; otherwise keep 2000 (macOS parity) and leave `max_keys=0`.
3. **D-06 — minimal sync anchor.**
   - Compute a stable anchor = hash (e.g. SHA-256, reuse the pattern behind `DS3Session.ComputeDiff`/SyncAnchorHash) over the **full** listing's sorted `key→etag` map (folders null-etag included). Computed only over the complete paginated set from Wave 1 — never a single page.
   - Persist per `(drive_id, prefix)` — add migration `003_prefix_anchor.sql` (a small `prefix_anchors` table) via `SchemaMigrator`, or reuse `singleton_state`. 
   - In `PollOnceAsync`, after listing, if the new anchor equals the stored one, skip `ComputeDelta`/`ApplyDelta` (emit Idle, log "unchanged") ; else apply and store the new anchor. Mirrors macOS `currentSyncAnchor` short-circuit.

## Tests
- **Progress:** enumeration over 3 pages raises `ProgressChanged` with monotonically increasing `ItemsSeen` and no key/file-name in the payload (assert the record has no string key field); hydration raises `BytesHydrated`.
- **Anchor short-circuit:** two identical listings → second poll performs no `ApplyDelta` (spy on store writes); a changed etag → full apply + new stored anchor.
- **Limiter:** concurrent enumerations never exceed the permit count (instrument max observed concurrency).
- **STRIDE:** a static/analyzer test asserts `DriveEnumerationProgress` exposes no file-name/key member.

## Done when
- Tray shows aggregate enumeration + hydration progress; no file names cross the status/progress channel.
- Unchanged prefixes skip the diff; changed ones still reconcile.
- Listing concurrency is bounded.
