# Phase 17.3 · Plan 02 (Wave 1): Full-pagination fix in the poll (D-01, the correctness bug)

**Goal:** The periodic poll enumerates the **entire** remote level before diffing, so no object beyond the first 2000-key page is ever misclassified as a deletion. This is the single most important correctness fix in the phase.

**Depends on:** Wave 0 (FakePagedSession).
**Decisions:** D-01.
**Criteria touched:** #2 (no missing/ghost entries at scale).

## Context

`SyncEngine.PollOnceAsync` (`windows/DS3Drive.Sync/SyncEngine/SyncEngine.cs:121`) issues a single `_session.ListObjectsListing(bucket, prefix, "/", null)` and never consults `IsTruncated` / `NextContinuationToken`. The diff (`ApplyDeltaAsync`, `SyncEngine.cs:264`) treats any locally-known key absent from `remoteMap` as `Deleted`. So for a prefix with >2000 direct children (`LIST_BATCH_SIZE = 2000`), pages 2+ are unseen → computed as deletions → placeholders pruned. `PlaceholderMaterializer.ListLevel` (`PlaceholderMaterializer.cs:71`) already implements the correct token-chasing loop — the fix aligns the poll with it and macOS `listAllRemoteChildren` (`apple/DS3DriveProvider/S3Enumerator.swift:280`).

## Tasks

1. **Extract a shared full-listing helper** so the poll and `ListLevel` cannot diverge again. Add `PlaceholderMaterializer.ListLevel` already returns a filtered `Level` (folders+files) by chasing the token — reuse it directly in the poll instead of the poll's own single-page loop. Replace `SyncEngine.PollOnceAsync` lines ~121–148 to:
   - Call `PlaceholderMaterializer.ListLevel(_session, bucket, prefix, ct)` (full pagination, already filters prefix-self / trailing-slash / `.ds3keep` / hidden).
   - Build `remoteMap` from `level.Files` (etag) + `level.Folders` (null etag), preserving the current folder-null-etag semantics (`SyncEngine.cs:145-148`).
   - Pass `level.Files` as the `remoteObjects` to `ApplyDeltaAsync` (was the ad-hoc `remote` list).
   - Keep the existing `IsInternalMarker` guard behavior (now handled inside `ListLevel`).
2. **Preserve the folder-deletion guard** — folders (common prefixes, null etag) must still round-trip so folder rows aren't pruned. `ListLevel` already returns them separately; ensure they land in `remoteMap` with null etag exactly as today.
3. **Cancellation + error parity** — retain the `BeginOperation`/`EndOperation(Idle|Error)` bracketing and the `OperationCanceledException` rethrow.

## Tests
- **Regression (the bug):** `FakePagedSession` scripts 2500 objects under the prefix across 2 pages; seed the placeholder store with the same 2500 rows; run `PollOnceAsync`; assert `delta.Deleted` is empty and no `DeleteAsync` occurred. (Before the fix this would prune ~500.)
- **True deletion still works:** remove 3 keys from the remote script, assert exactly those 3 are `Deleted`.
- **Folders not pruned:** common-prefix folders present locally + remotely (null etag) are neither re-applied nor deleted.
- Existing `EnumerationDiffApplicationTests` stay green.

## Done when
- The poll consumes all pages; the 2500-key regression test passes.
- No behavioral change for prefixes ≤2000 keys (existing tests green).
