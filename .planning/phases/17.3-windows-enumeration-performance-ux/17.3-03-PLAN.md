# Phase 17.3 · Plan 03 (Wave 2): Incremental streaming to Explorer (D-02) + on-disk ghost removal (D-03)

**Goal:** Placeholders appear in Explorer **per page as they arrive** (low time-to-first-item, no freeze at scale), and a remote deletion removes the on-disk placeholder, not just its DB row.

**Depends on:** Wave 1 (shared full-listing path).
**Decisions:** D-02, D-03.
**Criteria touched:** #1 (incremental, no freeze), #2 (no ghosts).

## Context

Both placeholder-creation paths buffer the whole level then emit one batch:
- `PlaceholderMaterializer.MaterializeAsync` (root, `PlaceholderMaterializer.cs:217`) → `ListLevel` (all pages in memory) → one `CfCreatePlaceholders`.
- `FetchPlaceholdersHandler.HandleAsync` (per-dir, `FetchPlaceholdersHandler.cs:73`) → `ListLevel` → one `CfExecute(TRANSFER_PLACEHOLDERS)` with `DISABLE_ON_DEMAND_POPULATION`.

macOS instead streams each page to the observer (`S3Enumerator.swift:123` `finishEnumerating(upTo:)`). And `ApplyDeltaAsync` deletion (`SyncEngine.cs:264`) drops only the DB row — no `CfDeletePlaceholders` — leaving possible on-disk ghosts.

## Tasks

1. **Page-streaming listing primitive.** Add `PlaceholderMaterializer.EnumerateLevelPages(session, bucket, prefix, ct)` returning `IAsyncEnumerable<Level>` (or a per-page callback) — one `Level` per S3 page, applying the same filters as `ListLevel`. Keep `ListLevel` as a thin "collect all pages" wrapper over it for the Wave-1 poll path (poll still needs the complete set for the diff — do NOT stream the poll).
2. **Root population (`MaterializeAsync`) streams:** for each page, `BuildLevel` → `CreatePlaceholders` (one `CfCreatePlaceholders` per page) → upsert that page's rows. Free pinned identity buffers per page. First page visible before later pages list.
3. **On-demand (`FetchPlaceholdersHandler`) streams via the cfapi multi-batch protocol.** Research item: `CfExecute(TRANSFER_PLACEHOLDERS)` supports multiple calls per fetch — intermediate batches omit `DISABLE_ON_DEMAND_POPULATION` and carry a "more data" completion (`STATUS_SUCCESS` with the batch's `EntriesProcessed`/`PlaceholderCount`), and only the **final** batch sets `DISABLE_ON_DEMAND_POPULATION` to mark the directory fully populated. Implement per-page `TransferPlaceholders`, tracking `EntriesProcessed` cumulatively; final page marks complete. Preserve the 30s-discipline (already deferred to a background `Task`) and the failure path (final batch with `StatusUnsuccessful`).
4. **Idempotency guard on re-enumeration.** Per-page create/transfer must remain idempotent: `(drive_id,s3_key)` upsert (`PlaceholderStore.cs:56`) + on-disk `ERROR_ALREADY_EXISTS` tolerance (`PlaceholderMaterializer.cs:275`) already cover repeats; confirm the streaming split doesn't double-count `EntriesProcessed` or drop the last page.
5. **D-03 — on-disk ghost removal.** In `ApplyDeltaAsync` `delta.Deleted` branch, after `PlaceholderStore.DeleteAsync`, remove the on-disk placeholder under the sync root. Add `PlaceholderMaterializer.DeletePlaceholder(localRootPath, key, drivePrefix, logger)` using `CfDeletePlaceholders` (or delete the placeholder file via the local path from `PathValidation.ResolveLocalPath`, guarding hydrated-dirty files). Tolerate not-found (already gone) and never delete a dirty local edit — skip + log if `IsDirty`. Requires the sync-root path in `SyncEngine`; it already holds `_localRootPath` (`SyncEngine.cs:38`).

## Tests
- **Streaming order:** `FakePagedSession` with 3 pages → assert `CreatePlaceholders`/`TransferPlaceholders` invoked 3 times, first before the third page is listed (inject a per-page barrier).
- **Final-page completion:** last transfer sets `DISABLE_ON_DEMAND_POPULATION`; earlier ones do not.
- **Idempotency:** run root materialize twice → placeholder rows unchanged, no exceptions, `ERROR_ALREADY_EXISTS` swallowed.
- **Ghost removal:** seed a synced (non-dirty) placeholder, delete it remotely, poll → DB row gone AND `DeletePlaceholder` called; dirty placeholder is preserved + logged.

## Done when
- Placeholders render progressively for a multi-page directory; no single giant batch.
- Remote delete removes the Explorer entry; dirty local edits survive.
