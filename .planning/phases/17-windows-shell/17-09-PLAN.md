<objective>
Build the drive setup wizard — the second WIN-02 milestone — and the DrivesListPage that becomes the post-tutorial landing page (Plan 08 left this as a TODO). The wizard expands Apple's collapsed 2-step `SyncSetupViewModel` (PATTERNS §2.5) into the 4-step C# state machine (Project → Bucket → Prefix → Confirm) mandated by D-09, with the API-key reconciliation algorithm ported byte-for-byte from `DS3SDK.swift:163-249` (PATTERNS §2.6 — load-bearing for cross-platform drive interoperability).

Purpose: This is where the user actually configures a drive: picks a project, then a bucket inside the project, then optionally a folder prefix, then confirms. After confirm, the wizard:
1. Runs `LoadOrCreateApiKey` (deterministic name pattern — same algorithm Apple uses → same API key visible in the Cubbit console).
2. Writes the drive to SQLite via DriveManagementService.AddAsync (persistence triple per PATTERNS §3.3).
3. Emits a "drive added" event that Plan 10's CfApiProvider listens for to register the cfapi sync root.

Output: A working wizard that creates a drive end-to-end (without the cfapi side — that's Plan 10), a DrivesListPage that lists drives with "Add drive" button (hidden at 3 per D-23), and tests covering the state machine + reconciliation algorithm.
</objective>

<!-- Deterministic name pattern (port of DS3SDK.swift:242-248 — DO NOT modify) -->
public static string ApiKeyName(DS3IAMUser user, string projectName) {
    var prefix = _configStore.ApiKeyNamePrefix;        // "ds3drive" from appsettings.json
    var sanitized = projectName.ToLowerInvariant().Replace(' ', '_');
    var installationId = _configStore.InstallationId;  // stable per-install GUID stored in SQLite on first run
    return $"{prefix}({user.Username}_{sanitized}_{installationId})";
}

<!-- DriveManagementService persistence triple (PATTERNS §3.3, port of DS3DriveManager.swift:244-248) -->
public async Task AddAsync(DS3Drive drive, CancellationToken ct) {
    _drives.Add(drive);                                  // 1. mutate in-memory
    await _db.UpsertDriveAsync(drive, ct);               // 2. persist to SQLite
    DriveAdded?.Invoke(this, drive);                     // 3. signal cfapi registration (Plan 10 subscribes)
    // Per PATTERNS §3.3: reversing 2 and 3 produces an orphan domain on persist failure.
}

        2. Load local API keys: `SELECT id, name, access_key, iam_user_id FROM api_keys WHERE iam_user_id = @userId` (secretKey separately from CredentialStore.Load(accountId, $"apiKey:{id}:secretKey")).

        5. Match by name. Apply the 4 branches:
           - Both present + equal (by Id and AccessKey) → return local.
           - Remote-only → DS3Session.DeleteApiKey(remote.Id) → fall through to create.
           - Local-only → DELETE FROM api_keys WHERE name = apiKeyName + CredentialStore.Delete → fall through to create.
           - Both present but differ → delete both → fall through to create.
        6. Create: `var created = DS3Session.CreateApiKey(user.Id, iamToken, apiKeyName);` → persist `INSERT INTO api_keys` + `CredentialStore.Save(accountId, $"apiKey:{created.Id}:secretKey", created.SecretKey)`.
