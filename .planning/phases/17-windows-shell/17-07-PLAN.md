<objective>
Deliver POL-01 (cross-FFI logging — pulled forward into Phase 17 per CONTEXT D-30): bridge Rust `tracing` events through the `ds3_set_log_callback` C ABI (Plan 01 / log_bridge.rs) to two C# `EventSource` providers (`Cubbit-DS3Drive-Core` for Rust events, `Cubbit-DS3Drive-App` for managed events) that surface in Windows Event Viewer / ETW.

Purpose: Without this plan, Rust core logs vanish at the FFI boundary; nothing surfaces in Event Viewer. The dispatch chain MUST be non-blocking — the Rust callback runs on a tokio worker thread and CANNOT call back into Rust on the same call stack (RESEARCH Pitfall 5). Channel + dedicated drainer thread is the canonical fix.

Output: A `RustLogBridge` that App.xaml.cs initializes once at startup; an `AppEventSource` that `Microsoft.Extensions.Logging.EventSource` plugs into via `AddEventSourceLogger`; a `RustCoreEventSource` that the Rust→C# dispatcher writes to.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Rust tracing event payload → C# managed string | Untrusted bytes (target + message) cross via `Marshal.PtrToStringUTF8` — must be length-bounded |
| ETW provider name → Event Viewer | Provider names are visible system-wide; collision with another tenant could cause confusion |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-07-01 | Tampering / EoP | Marshal.PtrToStringUTF8 with attacker-controlled length | mitigate | Length supplied by Rust (trusted side); cast to int with overflow check (`(int)Math.Min(len, int.MaxValue)`); copy into managed string; pointer not re-used after callback returns |
| T-17-07-02 | InfoDisclosure | Log payload leaking PII (token, email, secret) | mitigate | RustCoreEventSource events use structured args (target, message); ds3-* crates use `tracing::Span::record` with `.secret_` markers; documented review checklist for every `tracing::info!` in Rust crates; PATTERNS §3.6 discipline applied identically C# side |
| T-17-07-03 | DoS | Burst of high-frequency log events fills Channel | mitigate | BoundedChannelFullMode.DropOldest — caller never blocks; oldest events dropped silently |
| T-17-07-04 | DoS | Callback panic crashes the process | mitigate | Outer `try { ... } catch { }` swallow inside OnNativeCallback (CLR exception cannot unwind into Rust safely); critical errors logged via System.Diagnostics.Trace fallback |
| T-17-07-05 | EoP | FFI re-entrancy (callback → DS3Native → ... → callback) | mitigate | Channel indirection makes re-entry impossible; Pitfall 5 documented; Test 7 enforces with a thread-static reentry flag |
| T-17-07-06 | Spoofing | EventSource provider name collision | accept | "Cubbit-DS3Drive-Core/App" namespace is unique enough; no ETW provider registration conflict expected |
</threat_model>
