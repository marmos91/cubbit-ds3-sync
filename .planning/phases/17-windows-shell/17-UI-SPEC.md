# Phase 17 — UI Design Contract

> Visual and interaction contract for the WinUI 3 Windows shell. Generated by `gsd-ui-researcher`, verified by `gsd-ui-checker`. Pre-populated from `17-CONTEXT.md`, `17-RESEARCH.md`, and the existing macOS/iOS design system (`apple/DS3Lib/Sources/DS3Lib/DesignSystem/`).

## Scope

| Surface | Implementation | Notes |
|---------|----------------|-------|
| Login window | WinUI 3 `LoginPage` | Email + password + tenant + "Remember me". 2FA challenge on `TfaRequired`. |
| 2FA challenge | WinUI 3 `TwoFactorPage` | One-time 6-digit code field. |

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| `Space.xs` | 4px | Icon-to-label gap, inline padding inside pills |
| `Space.sm` | 8px | Compact element spacing (form field internal padding, list item vertical rhythm) |
| `Space.md` | 12px | Default element spacing between related controls in a column |
| `Space.lg` | 16px | Section padding inside cards; gap between unrelated controls |
| `Space.xl` | 24px | Section padding inside pages; gap between page sections |
| `Space.xxl` | 32px | Page-level outer padding (Login, Tutorial hero) |
| `Space.xxxl` | 48px | Major section breaks (Tutorial slide hero spacing) |

Exceptions:
- **Tray flyout outer padding:** 12px on all sides (constrained popup window, denser layout) — uses `Space.md`.
- **Tray drive row vertical rhythm:** 8px between status pill, name, and bucket/prefix line — uses `Space.sm`.
- **Wizard NavigationView pane:** 20px horizontal padding (Fluent v2 default `NavigationViewPaneCompactPadding`) — accept Fluent default, do not override.

Source: `DS3Spacing.swift` (4 / 8 / 12 / 16 / 24 / 32 / 48 scale) — verbatim port.

## Typography

Font family: **Figtree** (bundled in `Assets/Fonts/` and registered as application resource). Fallback chain: `Figtree, Segoe UI Variable, Segoe UI, sans-serif`.

Two weights declared (matches Apple's 2-weight discipline + medium for emphasis):

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| `Type.Display` | 32px | SemiBold (600) | 1.2 (38px) | Login screen "DS3 Drive" headline, Tutorial slide hero titles |
| `Type.H2` | 24px | SemiBold (600) | 1.2 (29px) | Wizard step titles ("Select a project"), Settings section headings |
| `Type.H3` | 18px | SemiBold (600) | 1.3 (23px) | Card headers, dialog titles, "Confirm your drive" |
| `Type.Body` | 14px | Regular (400) | 1.5 (21px) | Default body text, list rows, form labels, tray drive name |
| `Type.BodyMedium` | 14px | Medium (500) | 1.5 (21px) | Emphasized inline text, tray status pill label, recent-file names |
| `Type.Button` | 14px | SemiBold (600) | 1.2 (17px) | All button labels (primary + secondary) |
| `Type.Caption` | 12px | Regular (400) | 1.4 (17px) | Bucket/prefix sublabel under drive name, transfer-speed label, footnotes |

Letter spacing: default (0). Numerals: tabular (`FontFeatureSettings = "tnum"`) for transfer-speed labels and progress percentages.

**Constraint compliance:** 4 distinct sizes for content roles (Display / H2 / H3 / Body / Caption — H2 and H3 share a sub-heading axis but are necessary for IA depth on wizard + settings). Button shares Body size but different weight. Approved as 4 effective sizes for content + 1 utility (Button).

Source: `DS3Typography.swift` (Figtree scale 11/12/14/16/18/22/24/32/40 → trimmed to Windows-relevant 12/14/18/24/32; 40pt h1 dropped as Mica chrome supplies its own visual weight on Windows).

### Error states

Every error must state the **problem** and the **next step** in two sentences max. Use `InfoBar` (`Severity.Error`) for inline errors, `ContentDialog` for blocking errors.

| Scenario | Problem | Next step |
|----------|---------|-----------|
| Login — wrong credentials | **Sign-in failed.** | Check your email and password, then try again. |
| Login — 2FA required (auto-redirect) | _(no error; navigates to 2FA page)_ | — |
| Login — 2FA wrong code | **That code didn't work.** | Enter the 6-digit code from your authenticator app. |
| Login — network failure | **Can't reach Cubbit.** | Check your internet connection and try again. |
| Login — invalid coordinator URL | **Coordinator URL is invalid.** | Use a URL like `https://api.eu00wi.cubbit.services`. |
| Project picker — load failed | **Couldn't load projects.** | Check your connection and click **Retry**. |
| Drive creation — API key conflict | **A drive for this bucket already exists.** | Open the existing drive in the drives list, or pick a different bucket. |
| Drive creation — bucket permission denied | **Your account can't access this bucket.** | Contact your project administrator to request access. |
| Drive runtime — sync error (per-drive in tray) | **Sync error** (pill label) | Click for details. (Detail panel: full error message + **Retry** button.) |
| Drive runtime — coordinator unreachable | **Can't reach Cubbit. Retrying in 60 seconds.** | (auto-retry, no user action) |
| Drive runtime — disk space exhausted | **Not enough space on this PC.** | Free up space, then click **Resume**. |
| cfapi — NTFS check failed (install or wizard time) | **Cubbit DS3 Drive requires an NTFS volume.** | Choose a different folder location on an NTFS drive. |
| cfapi — sync root registration failed (sparse package missing) | **Setup couldn't finish.** | Reinstall Cubbit DS3 Drive and try again. (Log details available in **Settings → Logging → Open log folder**.) |

### Destructive actions

All destructive actions use `ContentDialog` with explicit consequence + a **destructive-styled** confirm button (red text, transparent fill, red `BorderBrush`). Cancel is the default.

| Action | Confirmation title | Confirmation body | Confirm button | Cancel button |
|--------|--------------------|--------------------|----------------|----------------|
| Sign out | **Sign out of Cubbit?** | Your drives will stop syncing on this PC. You can sign back in any time — no files will be deleted. | **Sign out** | **Stay signed in** |
| Remove drive | **Remove this drive?** | Files in `\Users\…\Cubbit\<drive>` will become unavailable here. Files in the bucket are not deleted. | **Remove drive** | **Cancel** |
| Quit DS3 Drive (from tray) | _(no confirmation — quit is non-destructive)_ | — | **Quit** (no dialog) | — |
| Uninstall (from Windows Settings) | _(handled by OS — no in-app dialog)_ | — | — | — |

**Microcopy rules** (enforced at review):
- Avoid "are you sure" — state the consequence instead.
- Never use "delete" for sign-out or drive removal (nothing is deleted on the server).
- Currency for time: "60 seconds" (spell out under one minute; "5 min" / "2 hr" beyond).
- Pluralize precisely: "1 file" vs "2 files" (no "1 file(s)").
- Status pill labels: **Synced** / **Syncing** / **Paused** / **Error** — single word, sentence case, no trailing punctuation.

## Interaction Contracts

### Focus & keyboard

- **Tab order:** standard top-to-bottom, left-to-right. Skip decorative elements.
- **Default button:** every form has exactly one `IsDefault = true` button (triggers on Enter). Sign-in form: Sign in. 2FA: Verify. Wizard steps: Continue. Drive confirm: Create drive. Destructive dialogs: Cancel (`IsDefault`), confirm is `IsCancel = false` and not default.
- **Escape:** dismisses dialogs and the tray flyout. Inside wizard, Escape on the first step closes the wizard (with no confirmation — no data persisted yet).
- **Focus visual:** Fluent v2 default high-contrast focus ring on every focusable control. Custom controls (StatusPill, TrayDriveRow) MUST keep `IsTabStop = false` unless they have a real action.

### Pointer & hover

- All interactive elements show pointer-cursor (`ProtectedCursor`).
- Hover states are accent-tinted at 8% alpha on `ListView` items and gear-menu buttons. **Hover tints MUST use `IsHitTestVisible = false` if rendered as overlays** — see project memory: "Filled `.overlay` shapes capture clicks even at opacity 0" — same trap applies to WinUI 3 `Rectangle` overlays inside `Grid` rows.

### Animation

- **Page transitions in NavigationView:** `SlideNavigationTransitionInfo` (default Fluent).
- **Dialogs:** Fluent v2 default scale-in.
- **Tray flyout open/close:** 150ms slide-up from tray with 200ms acrylic fade-in.
- **Sync state changes (status pill):** 200ms cross-fade between status color tokens (no spin/bounce animations — parity with macOS calm aesthetic).
- **Tray icon syncing:** 1s loop, accent dot fades in at 0–500ms and out at 500–1000ms. **No spinning glyphs** — Windows convention is subtle pulsing.
- **Loading rings:** Fluent v2 `ProgressRing` default rotation.

### Accessibility

- **All controls must have `AutomationProperties.Name`.** Icon-only buttons (gear menu, close, pause/resume) require `AutomationProperties.HelpText` describing the action.
- **Color contrast:** WCAG AA — verified against the dark theme palette. `Text.Primary` on `brandBg900` = 19.8:1; `brandPrimary` on `brandBg900` = 4.85:1 (passes large-text + UI-component); status colors all pass 4.5:1 against `brandBg800`.
- **Reduced motion:** when `UISettings.AnimationsEnabled = false`, skip flyout slide animation, skip pill cross-fade. Tray icon pulsing remains (it is an indicator, not decoration).
- **Screen reader:** Narrator announces sync status changes via `AutomationProperties.LiveSetting = Polite`. The tray-icon tooltip serves as the Narrator-visible state.
- **Keyboard-only:** entire flow completable without mouse (login → tutorial → wizard → drive). Tray flyout opened via the standard Windows shortcut (`Win + B` then arrow keys to system tray, Enter), exposed as a global hotkey is **out of scope**.
- **Touch targets:** all clickable controls ≥ 32×32px (matches Fluent v2 dense default; **exception:** TrayDriveRow gear button is 24×24 — acceptable because tray is mouse-target only).
- **High contrast mode:** WinUI 3 system handling — let Fluent v2 styles take over; only override brand brushes inside `ThemeDictionaries`.

### Tray-specific contracts

- **Single-click tray icon:** opens the flyout.
- **Right-click tray icon:** opens a compact `MenuFlyout` (Open Cubbit, Pause all / Resume all, Settings, Help, Quit) — quick actions without the flyout chrome.
- **Tray icon double-click:** opens the main drives-list window (parity with Windows convention).
- **Flyout dismissal:** lose focus → dismiss with 200ms fade; Esc dismisses; click outside dismisses.
- **State changes drive visible UI:**
  - Idle (all drives synced) → base Cubbit icon, tooltip: `DS3 Drive — Idle`.
  - Syncing (≥1 drive transferring) → base + pulsing accent dot, tooltip: `DS3 Drive — Syncing N files (M.M MB/s)`.
  - Error (≥1 drive errored) → base + static `statusErrorMain` dot, tooltip: `DS3 Drive — N drives need attention`.
  - Paused (≥1 drive paused, none syncing/error) → base + static `statusWarning` dot, tooltip: `DS3 Drive — N drives paused`.
- **Multi-state precedence:** Error > Syncing > Paused > Idle (highest-priority state wins the badge color and tooltip).

### Explorer sync state contracts (cfapi-driven, **not in-app UI**)

- The provider sets placeholder pin states (`FILE_ATTRIBUTE_PINNED`, `FILE_ATTRIBUTE_RECALL_ON_OPEN`) and reports per-file progress via `CfReportProviderProgress`. Explorer's status column and tile-view glyphs render automatically.
- **Do NOT** implement an `IShellIconOverlayIdentifier` (RESEARCH §Pattern 4 anti-pattern; CONTEXT D-19 superseded).
- Documented states: `In sync` (cfapi default), `Syncing` (during transfer), `Cloud-only` (placeholder, not hydrated), `Pinned` (always-available copy).

## Registry Safety

Phase 17 uses **no shadcn registry** (this is a WinUI 3 / XAML stack, not a React stack). All third-party components are declared in the C# package manifest and audited in `17-RESEARCH.md` §Package-Legitimacy-Audit.

| Source | Components used | Safety Gate |
|--------|-----------------|-------------|
| WinUI 3 / WindowsAppSDK (first-party Microsoft) | NavigationView, ListView, ContentDialog, InfoBar, ProgressRing, Button, TextBox, PasswordBox, etc. | not required — first-party |
| H.NotifyIcon.WinUI 2.4.1 (community, MIT) | `TaskbarIcon`, `MenuFlyout` integration | Planner inserts `checkpoint:human-verify` before `dotnet add package` per RESEARCH §Package-Audit; no UI registry safety gate applicable (no shadcn) |
| Vanara.PInvoke.CldApi 5.0.5 (community, MIT) | P/Invoke wrappers — **non-UI** | not applicable (system integration, no UI surface) |
