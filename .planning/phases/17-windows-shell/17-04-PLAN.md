<objective>
Author the sparse identity package manifest (and the supporting build script + app-side reference manifest) that grants the unpackaged WinUI 3 exe a package identity. Without this, `StorageProviderSyncRootManager.Register` throws `E_NOT_VALID_STATE` and the drive never appears in Explorer's sidebar (RESEARCH §Key Finding #1 + Pitfall 1).

Purpose: Per RESEARCH §"Architectural Responsibility Map", the sparse package is the linchpin between MSI distribution (D-28) and cfapi identity gating (WIN-03). The WiX MSI in Plan 12 will invoke `Add-AppxPackage -ExternalLocation` to register the manifest at install time; this plan delivers the manifest + build script the MSI consumes.

Output: Sparse identity manifest declaring `Cubbit.DS3Drive` with `uap10:AllowExternalContent=true`, `runFullTrust` capability, the cfapi extension declaration (`com.microsoft.storage.cloudfiles`), publisher subject placeholder matching the Authenticode cert; a PowerShell build script that packs + signs it; and an app-side `Package.appxmanifest` + `app.manifest` that link the exe to the identity.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Sparse package manifest → cfapi runtime | Cfapi trusts the package identity for sync root registration; malicious replacement could spoof the drive |
| Authenticode cert → SignTool | If cert private key leaked, attacker can sign a malicious sparse package with the same identity |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-04-01 | Spoofing | Sparse package identity (`Cubbit.DS3Drive`) | mitigate | Identity Name + Publisher subject locked in manifest; signed with Authenticode cert; load-bearing pitfall comment instructs cert procurement |
| T-17-04-02 | EoP | Sparse package version replay (RESEARCH Pitfall 7) | mitigate | Manifest leading comment documents the version-bump-per-release rule; Plan 12 (WiX MSI) automates the bump in its build pipeline |
| T-17-04-SC | Tampering | MakeAppx + SignTool (Windows SDK binaries) | accept | First-party Microsoft tooling shipped with VS / Windows SDK; no third-party install in this plan |
| T-17-04-03 | InfoDisclosure | CertPassword parameter in PowerShell history | mitigate | Parameter typed as `SecureString`; build-sparse.ps1 documented in comment to call from CI with secret pulled from secret store, not from interactive shell |
</threat_model>
