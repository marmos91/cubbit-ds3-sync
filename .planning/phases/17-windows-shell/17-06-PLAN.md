<objective>
Lay down the SQLite-backed persistence layer for the Windows sync engine. This is the Apple `SharedData` + `MetadataStore` analog (PATTERNS §3.4): drives + sync anchors + placeholder index live in SQLite at `%LOCALAPPDATA%\Cubbit\DS3Drive\sync.db` (D-11), credentials live in Credential Manager (Plan 05), no JSON files for runtime data (D-14).

Purpose: Plan 09 (drive setup wizard) writes drives; Plan 10 (cfapi sync engine) reads the placeholder index on every callback and updates it after every diff; Plan 11 (tray) lists drives. Without this plan, every later plan would be blocked on storage.

Output: A versioned SQLite database with five tables, a CRUD facade per concern (PlaceholderStore for placeholders; drive/sync_anchor/api_key/account_info CRUD on SyncDatabase directly for now — refactor into per-concern stores in Wave 2 if needed), and a pure-function `EnumerationDiff` ported verbatim from Apple's `EnumerationDiff.swift` (PATTERNS §2.13). Recovery: corrupt schema deletes the store and recreates (PATTERNS §2.12 — placeholder index is cache, not user data).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| S3 listing (network) → SQLite UPSERT | Object keys are user/network-controlled strings; cross into local storage |
| User-typed bucket / prefix → SQLite INSERT | Drive setup wizard inputs reach the database |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-06-01 | Tampering | SQLite injection via crafted S3 key or bucket name | mitigate | PlaceholderStore uses `SqliteParameter` exclusively (Test 10 verifies); no string interpolation in SQL |
| T-17-06-02 | InfoDisclosure | sync.db world-readable | mitigate | Path under `%LOCALAPPDATA%` is user-scoped ACL by default on Windows; documented in SyncDatabase doc comment |
| T-17-06-03 | DoS | Schema corruption blocks all sync | mitigate | Schema-recovery: delete + recreate (PATTERNS §2.12); placeholder index is cache, not user data — recovery is safe |
| T-17-06-04 | InfoDisclosure | Logs containing PII bucket / key names | mitigate | Logger usage names `s3Key` placeholder but never logs full key contents at Info level; Debug-only logs may include keys for diagnostics |
| T-17-06-SC | Tampering | Microsoft.Data.Sqlite 8.0.10 | accept | First-party Microsoft; already in central package management |
</threat_model>
