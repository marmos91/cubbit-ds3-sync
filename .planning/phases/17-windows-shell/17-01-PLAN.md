<objective>
Close the Rust C ABI surface gap so the Windows shell (Phase 17 Waves 1-4) can consume every operation the macOS app currently uses, AND add the POL-01 Rust-side logging callback (`ds3_set_log_callback`) that bridges Rust `tracing` events to the C# `EventSource` host in DS3Drive.Core.

Purpose: Without this plan, Wave 1 P/Invoke bindings would compile but link-error or crash at runtime when the C# layer tries to call functions that only exist on the UniFFI surface. Per RESEARCH §Key Finding #2 and §Pitfall 6, the C ABI must be a strict superset of Windows callers' needs, and the DLL artifact name (`ds3_ffi`, NOT the `ds3_core` mistakenly used in CONTEXT.md D-06) must be reconciled here once.

Output: Updated `core/ds3-ffi/src/c_exports.rs` with the missing gaps closed; new `core/ds3-ffi/src/log_bridge.rs`; new Windows DLL build scripts; CONTEXT.md note about the artifact name kept as `ds3_ffi`.

    - Test 1: set_callback(Some(captured)); tracing::info!(target: "test", "hello"); assert captured received (2, "test", "hello").

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| C# → Rust C ABI | Untrusted UTF-8 strings + lengths flow from the managed runtime into Rust; Rust must validate before use |
| Rust tracing event → C callback → C# EventSource | Log payloads cross the FFI boundary; PII must not appear in event arguments |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-01-01 | Tampering | `ds3_set_log_callback` — caller-supplied function pointer | mitigate | `set_callback` stores into AtomicPtr; null check on every dispatch; documented re-entrancy ban (Pitfall 5) |
| T-17-01-02 | Tampering / EoP | All new `extern "C"` functions taking `*const u8, usize` | mitigate | Length-bounded `slice::from_raw_parts` reads only; null-pointer check before deref; ffi_guard! catches panic and returns DS3Error code (9999) |
