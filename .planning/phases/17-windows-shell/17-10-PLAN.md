<objective>
This is the heaviest plan of the phase — it delivers the entire cfapi sync engine. Wave 1 prepared persistence + the FFI facade; Wave 2 lit up the UI; Wave 3 connects everything to Windows Explorer via cfapi callbacks.

The pieces:
1. **Sync root registration** (WIN-03): `StorageProviderSyncRootManager.Register` (requires sparse package identity from Plan 04) + `CfConnectSyncRoot` + callback table.
2. **On-demand hydration** (WIN-04, WIN-08): `CF_CALLBACK_TYPE_FETCH_DATA` streaming S3 download in 4KB-aligned chunks with `CfReportProviderProgress` (Pitfall 2 — 30-second timeout).
3. **Upload on file close** (WIN-05): `NOTIFY_FILE_CLOSE_COMPLETION` triggers upload only when the placeholder is dirty (Pitfall 3 — no spurious re-upload after hydration); rename and delete callbacks handle the other mutations.
4. **Periodic polling for remote changes** (WIN-06): per-drive `PollingTimer` runs `DS3Session.ComputeDiff` every 60s (D-18), applies diff to placeholders, triggers status updates.
5. **Tray-relevant status** (WIN-07 prep): `DriveStatusBroadcaster` ports `NotificationsManager.swift` byte-for-byte (PATTERNS §2.8 — load-bearing per project memory "NotificationManager Operation Counter").
6. **Cross-cutting safety**: path validation, NTFS volume check (Pitfall 8), HTTP/2 stream limiter (PATTERNS §3.5), STRIDE Tampering mitigations.

Purpose: Without this plan, the wizard creates drives that don't appear in Explorer, files don't hydrate, files don't upload — i.e., the entire user-facing value of Phase 17 is dark. This is the highest-risk plan; its anti-patterns are documented exhaustively in RESEARCH because they cost Apple-side and the Cloud Mirror sample documented engineers many days/weeks.

Output: A SyncHostedService that, when a drive is added (Plan 09 event), spins up a CfApiProvider + SyncEngine; on remove, tears them down cleanly; on app shutdown, stops every drive gracefully. The sync root appears in Explorer's sidebar; double-clicking a cloud-only file hydrates it with visible progress; saving uploads it; remote changes appear within one polling cycle.
</objective>
