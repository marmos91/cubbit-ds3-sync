<objective>
Build the DS3Drive.Core P/Invoke facade. This is the single layer through which the Sync and App projects interact with the Rust core. It owns:
1. csbindgen-generated `DS3Native.cs` (internal, raw IntPtr / pointer math).
2. Hand-written `DS3Session : IDisposable` (idiomatic C# methods, throws typed exceptions, no IntPtrs leak out).
3. The exception hierarchy parallel to Apple's enum tree (Phase 16 D-15 byte-identical 2FA mapping).
4. Domain record types (DS3Drive, DS3Project, DS3Bucket, DS3ApiKey, DS3AccountInfo, DS3SyncAnchor) mirroring `ds3-models`.
5. `CredentialStore.cs` wrapping Windows Credential Manager (`CredWrite`/`CredRead`/`CredDelete`).
6. `ConfigStore.cs` reading `appsettings.json` defaults.
7. Wave-0 test scaffolding: DS3SessionTests (auth Smoke), DS3ExceptionFactoryTests (every code), CredentialStoreTests (round-trip).

Purpose: Wave 1 establishes the API contract every later plan codes against. The 2FA error mapping (D-15) is load-bearing — Apple's UI already depends on it and Windows must match byte-identically. Credential Manager (D-12) is the unpackaged-app equivalent of Apple's App Group container for secret storage.

Output: A buildable DS3Drive.Core with the full FFI facade, exception hierarchy, records, secure storage, and TDD test coverage on the deterministic parts (exception factory, credential round-trip, session lifecycle smoke).
</objective>

| User credentials → Credential Manager → DPAPI | Secrets cross from process memory into the OS-managed DPAPI store |

| T-17-05-01 | Tampering / EoP | FFI string len parameter | mitigate | `byte[] utf8 = Encoding.UTF8.GetBytes(s); fixed (byte* p = utf8) DS3Native.fn(p, (nuint)utf8.Length, ...)`; never accept caller-supplied lengths |
