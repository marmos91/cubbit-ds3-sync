<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Rust -> Cubbit IAM API | HTTP requests carrying credentials cross trust boundary |
| Password in memory | Password used for SHA256 seed derivation, then discarded |
| JWT tokens | Access tokens and refresh tokens stored in DS3Session |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-04 | Information Disclosure | tracing logs | mitigate | `#[instrument(skip(password, secret_key, signed_challenge))]` on all auth functions; never log credentials |
| T-15-05 | Information Disclosure | DS3Error Display | mitigate | ServerError includes status code but not full response body in Display (body stored in field for debug only) |
| T-15-06 | Tampering | HTTPS enforcement | mitigate | CubbitAPIURLs.default_coordinator_url starts with `https://`; reqwest defaults to TLS verification enabled. No `danger_accept_invalid_certs` calls. |
| T-15-07 | Spoofing | JWT validation | mitigate | Token expiry checked via `exp` field before use; jsonwebtoken decode validates structure |
| T-15-08 | Denial of Service | ed25519 panic | mitigate | ed25519-dalek `SigningKey::from_bytes` is infallible (accepts any 32 bytes); `sign` is also infallible. No panic path in crypto. |
| T-15-SC | Tampering | cargo installs (ed25519-dalek, sha2) | mitigate | Crypto crates are [ASSUMED] per audit. Both from RustCrypto/dalek-cryptography -- well-known maintainers. First credential use triggers human awareness via integration test plan (15-07). |
</threat_model>
