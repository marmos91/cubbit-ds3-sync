    **Step A — Create `DS3DriveProvider/ThumbnailFetchLimiter.swift`:**

    Mirror `BucketListingLimiter`'s API (acquire / release with continuation queue). Per D-12, slots = 4 on macOS. Per Pitfall 4, this limiter ONLY wraps the consume path — never used by uploader or coordinator.

    ```swift
    import Foundation

    /// Caps concurrent S3 GET requests for thumbnail consumption (`fetchThumbnails`)
    /// to avoid S3 SlowDown under bursty Finder folder-open fanout.
    /// Slots = 4 on macOS (Phase 13 D-12, THUMB-14). Upload-path and backfill coordinator
    /// have their own concurrency lanes — DO NOT route them through this limiter (Pitfall 4).
    /// NOTE on lifecycle / deinit: ThumbnailFetchLimiter is owned by FileProviderExtension
    /// (held as `private let thumbnailFetchLimiter = ...`). The extension instance lives
    /// for the entire extension process lifetime — `fileproviderd` only releases it on
    /// process exit. Therefore deinit-while-waiters-are-suspended is structurally
    /// impossible in production: by the time the limiter would be deinited, the process
    /// is exiting and any suspended continuations are torn down with the process. We do
    /// NOT need a deinit hook to resume orphan continuations. (See Plan 13-06 W2.)
    actor ThumbnailFetchLimiter {
        private let maxSlots: Int
        private var inFlight = 0
        private var waiters: [CheckedContinuation<Void, Never>] = []

        init(maxSlots: Int) {
            self.maxSlots = maxSlots
        }

        func acquire() async {
            if inFlight < maxSlots {
                inFlight += 1
                return
            }
            await withCheckedContinuation { (cont: CheckedContinuation<Void, Never>) in
                waiters.append(cont)
            }
            // After resume, the slot was already counted by release().
        }

        func release() {
            if let next = waiters.first {
                waiters.removeFirst()
                next.resume()  // resume holds the slot transferred from us
            } else {
                inFlight -= 1
            }
        }

        /// Convenience helper — wraps acquire/release around an async block.
        func withSlot<T: Sendable>(_ block: @Sendable () async throws -> T) async rethrows -> T {
            await acquire()
            defer { Task { await release() } }
            return try await block()
        }
    }
    ```

    Note on the `defer`: `release()` is async (actor-isolated); a sync defer can't `await`, so we spawn a child Task. This is acceptable because release() is fast and never throws. (Alternative: don't use `withSlot` and do explicit acquire/release at the call site — your discretion.)
