# Phase 13.2 Plan 03: Upload-hook signalEnumerator Summary

Adds the post-PUT `signalEnumerator(for: parentContainer)` to the upload-hook detached
Task so a fresh upload (which writes BOTH the original and `.thumbnails/<key>.jpg`)
nudges Apple to re-enumerate the parent folder — symmetric with the fallback path
shipped in Plan 02. The user now sees thumbnails appear after upload without
restarting Finder or refreshing.

## What changed

- **`ThumbnailUploadHookContext`** gained `domain: NSFileProviderDomain` (the field
  the detached Task needs to construct an `NSFileProviderManager`). Free-function
  contract preserved — Sendable bundle stays Sendable-clean at construction.
- **Post-PUT signal block** added inside `enqueueThumbnailUpload`'s detached Task
  on the success path only (D-12). Computes the parent identifier via
  `S3PathUtils.parentKey(forKey:drivePrefix:)`; falls back to `.rootContainer`
  for items at the drive root.
- **Test seam:** `enqueueThumbnailUpload` accepts an optional
  `signalParentContainer: (@Sendable (NSFileProviderItemIdentifier) -> Void)?`.
  Production passes `nil` (production default builds an `NSFileProviderManager`-backed
  closure via `defaultSignalParentContainer`). Tests inject the recorder closure
  used in `ThumbnailHybridConsumeTests.swift` (shared `SignalRecorder` actor).
- **Internal helper extraction:** the Task body moved into a private async helper
  `runUploadHook(...)` to sidestep an `ambiguous use of 'detached(name:priority:operation:)'`
  Swift 6 overload-resolution failure when the Task body captured a `@Sendable`
  closure alongside other Sendable locals. The helper preserves all Sendable invariants.
- **Both upload-hook callsites** in `+Create.swift` and `+Modify.swift` (content-change
  branch) updated to pass `domain: self.domain`.
- **Test fixture:** `ProviderTestFixtures.makeDomain()` added so tests can satisfy the
  `domain:` parameter without standing up a real File Provider.

## Tests

### New tests in `UploadHookTests.swift`

1. **`testUploadHookSignalsParentContainerAfterSuccessfulPut`** — asserts that after
   a successful PUT the injected `signalParentContainer` closure is invoked exactly
   once with the parent of the original key (`prefix/folder/photo.jpg` →
   `prefix/folder/`).
2. **`testUploadHookDoesNotSignalWhenPutFails`** — asserts that on PUT failure the
   signal closure is NOT invoked (negative path; nothing to re-enumerate).

## Decisions

- **D-12 honored:** signalEnumerator on parent container only; `S3Item.itemVersion.contentVersion`
  stays derived from `sourceETag` exclusively (no thumb-availability bit). Symmetric with
  the fallback path shipped in Plan 02.
- **Closure-injection seam mirrors Plan 02:** uses the same `SignalRecorder` actor type from
  `ThumbnailHybridConsumeTests.swift`. The test-only `signalParentContainer:` parameter
  defaults to `nil` so production callsites stay compact and the production path uses the
  `NSFileProviderManager`-backed closure built by `defaultSignalParentContainer(...)`.
- **`error.localizedDescription` allowed on the signal callback:** `signalEnumerator`
  returns a vanilla `NSError`, not a Soto error, so the codebase-wide `describeSotoError`
  rule does not apply. Justified inline with a comment.
- **Helper extraction (`runUploadHook`):** required to sidestep a Swift 6 overload-resolution
  ambiguity inside `Task.detached`. Preserves the Sendable contract — every captured
  parameter is Sendable; `self` is never captured.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking issue] Task.detached overload ambiguity**
- **Found during:** Task 1 GREEN implementation
- **Issue:** Inline `Task.detached(priority: .background) { ... }` containing both
  `@Sendable` closure capture and `try`-`catch` triggered Swift 6.2's
  `Task.detached(name:priority:operation:)` ambiguous-overload error.
- **Fix:** Extracted Task body to private `@Sendable` async helper `runUploadHook(...)`.
  The Task body now contains a single async call, which the compiler resolves cleanly.
  Sendable contract preserved.
- **Files modified:** `DS3DriveProvider/FileProviderExtension+ThumbnailUploadHook.swift`
- **Commit:** `52a2571`

**2. [Rule 3 - Blocking issue] `NSFileProviderItemIdentifier.init` is ambiguous**
- **Found during:** Task 1 GREEN implementation
- **Issue:** `parentKey.map(NSFileProviderItemIdentifier.init)` failed with
  "ambiguous use of 'init'" — the type has multiple init overloads.
- **Fix:** Used explicit closure `parentKey.map { NSFileProviderItemIdentifier($0) }`.
- **Files modified:** `DS3DriveProvider/FileProviderExtension+ThumbnailUploadHook.swift`
- **Commit:** `52a2571`

**3. [Rule 3 - Blocking issue] SwiftLint `function_parameter_count` on `runUploadHook`**
- **Found during:** Task 1 commit (post-edit pre-commit hook)
- **Issue:** Extracted helper `runUploadHook` has 8 parameters; SwiftLint default limit is 6.
- **Fix:** Added `// swiftlint:disable function_parameter_count` / `enable` block around the
  helper. Inline comment explains the trade-off (the alternative is yet another Sendable struct
  for an internal helper).
- **Files modified:** `DS3DriveProvider/FileProviderExtension+ThumbnailUploadHook.swift`
- **Commit:** `52a2571`
