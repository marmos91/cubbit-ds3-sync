# Phase 13.2 Plan 06: Delete BFS Indexer + Hook Runner Stack — Summary

Removed the entire BreadthFirstIndexer subsystem (indexer, pass-tail hook runner, their tests) and every callsite that touched it. With Wave 1-2 reactive paths already live, BFS was pure overhead — Apple's `enumerateItems` already drives per-folder listing on demand, and the cache-miss fallback render path covers thumbnail materialization that BFS used to handle indirectly.

## What changed

- **Deleted** (3 files, 832 LoC):
  - `DS3DriveProvider/BreadthFirstIndexer.swift` (388 LoC) — proactive level-by-level S3 scanner with the embedded `QueueManager` actor + lazy `ThumbnailBackfillCoordinator` + lazy `OrphanSweeper`.
  - `DS3DriveProvider/BFSThumbnailHookRunner.swift` (182 LoC) — pass-tail hook runner with `ThumbnailBackfillRunning` + `OrphanSweeping` test-injection seam protocols.
  - `DS3DriveProviderTests/BFSThumbnailHookTests.swift` (262 LoC) — unit tests for the hook runner.
- **Modified**:
  - `FileProviderExtension.swift` — dropped `breadthFirstIndexer` property, invalidate teardown, and the `prioritize(prefix:)` call inside `materializeFolderItem`. Updated init to call the renamed `warmCache()` instead of `warmCacheThenStartBFS()`. Updated doc comment on `materializeFolderItem` to reflect that child discovery is reactive.
  - `FileProviderExtension+Lifecycle.swift` — renamed `warmCacheThenStartBFS()` → `warmCache()`, deleted three `startBFSIndexer()` call sites + the entire `startBFSIndexer()` method + the BFS Indexer MARK section. Cache warm-up itself preserved (still useful — it primes MetadataStore).
  - `OrphanSweeper.swift` — removed the orphan `extension OrphanSweeper: OrphanSweeping {}` conformance (the `OrphanSweeping` protocol is gone with the BFSThumbnailHookRunner.swift file). The `OrphanSweeper` struct itself is left intact for Plan 07.
  - `DS3Drive.xcodeproj/project.pbxproj` — removed all PBXFileReference, PBXBuildFile, PBXGroup, and Sources buildPhase entries for the three deleted files (10 entries cleaned).
