# Phase 13.2 Plan 09: Schema V6 — drop thumbnailStatus + fetchPendingThumbnails Summary

**SwiftData V5→V6 lightweight migration drops `thumbnailStatus` field + `fetchPendingThumbnails`/`setThumbnailStatus` queries; strips `markPending` parameter from `consumeThumbnail`; removes all `.notApplicable`/`.uploaded`/`.pending` writes from upload hook, uploader, and rename cascade. Final schema cleanup of the thumbnail subsystem — no thumbnail-specific SwiftData fields remain.**

## Accomplishments

- **Schema V6 ships and migrates cleanly.** `SyncedItemSchemaV6` defined with `@Attribute(hashModifier: "v6")` on `s3Key` to dodge the duplicate-checksum trap (V6 is structurally identical to V2 after V3/V4/V5 add-then-remove churn). `migrateV5toV6` lightweight stage added; `SyncedItem` typealias bumped to V6; `MetadataStore` container schema bumped to V6. `SchemaV6MigrationTests` validates V5→V6 round-trip preserves all 3 seeded rows + the SyncAnchorRecord (Pitfall 3 regression guard).
- **All thumbnailStatus writes removed from production code.** Per D-08, `.notApplicable` (upload hook non-raster branch + uploader pre-filter), `.uploaded` (uploader success), and `.pending` (rename cascade copy-failure + applyUpsert ETag-change re-arm) writes are gone in the same plan that ships V6 — no orphaned writes against the dropped column.
- **`consumeThumbnail` signature simplified.** `markPending` parameter stripped (no consumer remains after BFS coordinator deletion in Plan 07). The cache-miss sentinel `(nil, NSFileProviderError(.noSuchItem))` is now the sole signal the caller's interceptor uses to route into `consumeThumbnailFallback` (Plan 02 reactive render path).
- **Query surface cleaned up.** `fetchPendingThumbnails` and `setThumbnailStatus` deleted from `MetadataStore+Queries`; obsolete `MetadataStoreThumbnailQueriesTests.swift` deleted entirely.
- **Full DS3Lib suite passes (529/529).** All schema migration tests (V3, V4, V5, V6) green; SyncEngineTests, MetadataStoreTransientStatusTests, MetadataStorePurgeTests, ConflictDetectionTests, MetadataStoreMigrationTests, Phase13IntegrationSmokeTests, ThumbnailUploaderTests all green after V6-binding setUp methods.
- **xcodebuild test green except for 2 pre-existing failures** (`S3ItemTests.testDecorationSynced`, `testDecorationCloudOnlyDefault`) — both documented in `deferred-items.md` as out of scope for this phase (decoration regression unrelated to thumbnail subsystem).

## Decisions Made

- **Retain `metadataStore` parameter on `ThumbnailUploader.init` and `enqueueThumbnailRenameCascade`** even though no thumbnail-specific writes happen — preserves call-site stability and leaves the seam open for future use. Justified inline with `_ = (metadataStore, driveId)` to silence unused-variable warnings.
- **Cascade copy-failure path drops the `.pending` write entirely** rather than substituting an alternative signal. The absence of `.thumbnails/<newKey>.jpg` in S3 is now the sole forward-progress signal — the consume-path fallback (Plan 02) observes it on next user-visible visit and re-renders from the new original.
- **`applyUpsert` no longer re-arms thumbnailStatus on ETag change** — the field is gone, and the consume-path fallback re-renders on every cache miss anyway, so the legacy re-arm is structurally redundant.
- **`@Attribute(hashModifier: "v6")` applied to `s3Key`** to disambiguate V6 from V2 — V6 is structurally identical to V2 after the V3/V4/V5 add-then-remove churn, which would trip SwiftData's "Duplicate version checksums across stages" guard. Mirrors the V5 fix from Plan 08 and pinned in code comments + test rationale.
