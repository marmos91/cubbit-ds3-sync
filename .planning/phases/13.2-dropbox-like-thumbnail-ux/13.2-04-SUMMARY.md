## Decisions Made

1. **Programmatic fixture over Git LFS.** Plan offered both options. Chose programmatic because (a) avoids 50 MB binary in repo history, (b) avoids Git LFS dependency for CI runners, (c) makes D-18 enforceable on first run, no perpetually-skipped XCTSkip path. Cached in `NSTemporaryDirectory()/ds3drive-13.2-04-large.heic` so subsequent test runs reuse the file (only the first run pays the ~1s generation cost).

2. **`task_vm_info_data_t.phys_footprint` instead of `mach_task_basic_info`.** Plan referenced `mach_task_basic_info` as the primitive used by `logMemoryUsage`, but the actual codebase primitive in `DS3Lib/Sources/DS3Lib/Utils/MemoryLogger.swift` is `task_vm_info_data_t.phys_footprint`. Using the matching primitive ensures the test asserts on the same metric the extension logs in production. Plan's interface block self-described as "Approximate shape (verify exact lines on read)" — followed that guidance.

3. **Assert delta, not absolute.** XCTest runner has its own resident-memory overhead that varies by macOS / Xcode version. Asserting `peak - baseline` decouples the test from runner overhead and measures only the renders' contribution.

4. **JPEG encoder fallback in fixture generator.** If HEIC encoder is unavailable on the test runner (rare on macOS but possible in headless CI environments), the generator transparently falls back to JPEG. `ThumbnailRenderer` accepts JPEG too (`public.jpeg` is in `allowedRasterUTIs`) and the mmap path is format-agnostic, so the smoke test's purpose is preserved.
