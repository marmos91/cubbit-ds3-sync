## Executive Summary

Phase 13.2 replaces the BFS-driven thumbnail subsystem with a reactive, Apple-API-driven 3-lane model. The cold-folder UX bug (5–30 minute wait for the indexer to chew through the bucket before any thumbnail appears) is now solved **structurally** — there is no global pass to wait for. Instead:

1. **Lane 1 — Cache hit.** `fetchThumbnails` reads `.thumbnails/<key>.jpg` from S3 first.
2. **Lane 2 — Cache-miss fallback.** Download original, render JPEG locally, return bytes to Finder via `perThumbnailCompletionHandler` immediately.
3. **Lane 3 — Background backfill PUT.** Fire-and-forget `Task` PUTs the rendered JPEG to `.thumbnails/<key>.jpg`, then `signalEnumerator(parentContainer)` so the next visit hits Lane 1.

Apple's `enumerateItems` drives per-folder discovery on demand. Cascades (Phase 13) handle rename/delete propagation. There is no longer an indexer, no backfill coordinator, no orphan sweeper, no rollout driver, no thumbnailFailCount field, no thumbnailStatus field. The 3-lane model + cascades + upload-time generation is the entire feature.

## Realized Decisions (D-01 through D-26)

All 26 user decisions from `13.2-CONTEXT.md` are realized at this gate. Each decision is paired with its realizing plan and a brief realization note.

### Feature shape (locked spine)

- **D-01 — 3-lane fetchThumbnails (cache hit / fallback render / background PUT) in strict order.** Realized in **Plan 02** (`consumeThumbnailFallback` free function in `+ThumbnailConsume.swift`). Cache-miss is intercepted in `spawnCacheFirstThumbnailTask` via the unique `(nil, NSFileProviderError(.noSuchItem))` sentinel.
- **D-02 — 4-slot ThumbnailFetchLimiter for cached path; new 2-slot ThumbnailFallbackLimiter for fallback. Strict separation.** Realized in **Plan 01** (limiter actor) + **Plan 02** (caller wiring). Detached PUT releases the cache (4-slot) limiter before fallback acquires its own (2-slot) slot — keeps the cheap hot path unblocked under load.
- **D-03 — Mixed cache-hit/cache-miss batches: hits return immediately, misses stream completions to the same `perThumbnailCompletionHandler`.** Realized in **Plan 02** via interceptor closure + 2-at-a-time fallback fork.
- **D-04 — Single render per cache miss: bytes returned to Finder are the same bytes PUT to S3.** Realized in **Plan 02** — the rendered `Data` is reused verbatim by the detached PUT Task.

### Schema cleanup

- **D-05 — Schema V5 drops `thumbnailFailCount`; Schema V6 drops `thumbnailStatus` + `fetchPendingThumbnails`.** Realized in **Plan 08** (V5) and **Plan 09** (V6).

- **D-08 — Upload-hook `.notApplicable` / `.uploaded` writes removed in the same plan that ships V6.** Realized in **Plan 09** (`+ThumbnailUploadHook.swift`, `ThumbnailUploader.swift`, `+ThumbnailCascade.swift`, `MetadataStore.applyUpsert`).

### Cache invalidation strategy

- **D-12 — Post-PUT `signalEnumerator(parentContainer)`. No thumb-availability bit on `S3Item.itemVersion.contentVersion`.** Realized in **Plan 02** (fallback path) and **Plan 03** (upload hook). Verified by grep that no `.contentVersion` mutation exists in `+Thumbnails.swift` or `+ThumbnailUploadHook.swift`.

- **D-18 — Memory smoke test target: 8 sequential 50 MB HEIC files; peak resident under 50 MB ceiling.** Realized in **Plan 04** (`ThumbnailFallbackMemorySmokeTests`). Programmatic fixture generator avoids Git LFS dependency. Test passes in 5.25s with peak-delta in the low-single-digit MB range.

### Strike counter / negative cache

- **D-19 — `ThumbnailFallbackLimiter` actor holds `[String: Int]` strike counter + `Set<String>` poison set, in-memory only, reset on extension launch.** Realized in **Plan 01**.

- **D-21 — In-memory only is acceptable: extension is long-lived; real-world poison files are rare; persisted poison sets introduce a stale-state bug surface.** Honored — no `SyncedItem` thumbnail field added.

- **D-22 — Additive paths ship before deletions; build green at every commit.** Honored: Wave 1 (Plans 01, 02, 03) shipped fallback limiter + fork + signalEnumerator; Wave 2 (Plan 04) added smoke test; Wave 3 (Plan 05) collapsed tray; Wave 4 (Plans 06, 07) deleted BFS stack + coordinator + sweeper; Wave 5 (Plan 08) shipped Schema V5; Wave 6 (Plan 09) shipped Schema V6; Wave 7 (Plan 10) ship gate. ### Pause / resume

- **D-24 — Per-handler `SharedData.isDrivePaused` check; no backfill engine to halt.** Realized in **Plan 02** (fallback path checks pause BEFORE acquiring a 2-slot limiter slot) and **Plan 03** (upload hook checks before its post-PUT render).

## Manual Smoke Test Checklist (Pre-Merge)

Before merging this branch, the engineer running the build must perform the following manual smokes (`Cmd+R` from Xcode):

### 1. Cold-folder UX (THUMB-15)

- [ ] Mount a drive whose bucket has 20+ JPEG/HEIC files in a never-visited folder.
- [ ] Open the folder in Finder.
- [ ] Within ~3s, thumbnails appear progressively (Lane 2 fallback render).
- [ ] Wait ~5s, close the folder, reopen it.
- [ ] Thumbnails appear instantly (Lane 1 cache hit — backfill PUT landed).
- [ ] Confirm via Activity Monitor that `DS3DriveProvider` extension peak resident memory stays under ~50 MB throughout.

### 2. Pause/resume halts fallback (THUMB-21)

- [ ] Click the tray icon → Pause drive.
- [ ] Browse a new folder with images that haven't been thumbnailed yet.
- [ ] No thumbnails appear (fallback gated; default UTType icons shown).
- [ ] Verify via `log stream --predicate "subsystem == 'io.cubbit.DS3Drive.provider'" --info --debug` that "Fallback: drive paused" log lines appear.
- [ ] Click Resume.
- [ ] Within seconds, thumbnails appear (fallback resumes on next visit/refresh).

### 3. Tray `.indexing → .sync` UX (D-16)

- [ ] Browse a 1000+ item folder.
- [ ] Tray icon shows "syncing" / "busy" indicator (NOT "indexing").
- [ ] When listing completes, tray returns to "idle".

### 4. Cascade after rename (THUMB-19, D-15)

- [ ] Rename a thumbnailed image in Finder.
- [ ] Wait one sync cycle (~30s).
- [ ] The renamed file shows a thumbnail.
- [ ] Use the AWS CLI or S3 console to verify `.thumbnails/<oldKey>.jpg` is gone, `.thumbnails/<newKey>.jpg` exists.

### 5. Memory ceiling under sustained fallback (D-18)

- [ ] Open a folder containing 8+ large (~50 MB) HEIC files in the bucket.

- [ ] Peak memory stays under ~50 MB throughout the 8 sequential renders.

- [ ] On a Mac that ran Phase 13.1 (V4 schema) before installing 13.2: launch the app.
- [ ] Confirm no migration errors in `log show ... subsystem == 'io.cubbit.DS3Drive' AND category == 'sync'`.
- [ ] Confirm metadata still appears (drives load, file lists populate).

## Key Patterns Established

- **Free-function detached `Task` with sendable capture.** `consumeThumbnailFallback` (Plan 02) and `enqueueThumbnailUpload` (existing, extended in Plan 03) are free `@Sendable` functions taking a Sendable context bundle. The detached `Task` captures only sendable locals; `self` is never captured. Pattern for any future post-handler async side-effects.
- **Per-handler pause gate before slot acquisition (THUMB-21 satisfaction pattern).** Each handler reads `SharedData.isDrivePaused(driveId)` BEFORE acquiring a limiter slot. No paused drive ever blocks a limiter pool.
- **In-memory limiter-owned state for terminating reconciliation.** `ThumbnailFallbackLimiter` owns the 3-strike state in process; persistence is intentionally absent. Pattern for any negative-cache where the failure mode is deterministic (decode failure, not transient network).
- **Schema removal pattern: lightweight migration + `@Attribute(hashModifier:)` sentinel.** SwiftData throws `Duplicate version checksums across stages` when a new schema is structurally identical to an earlier one (V5 ≡ V3, V6 ≡ V2 in this phase's churn). `@Attribute(hashModifier: "vN")` on any field forces a distinct schema checksum. Validated for two consecutive removal migrations.
- **"Less is more" — Apple framework drives reactivity; we don't run an indexer.** `enumerateItems` + cache-miss fallback + `signalEnumerator` after PUT covers everything BFS used to do, with structurally bounded peak memory and zero global-pass UX latency.
