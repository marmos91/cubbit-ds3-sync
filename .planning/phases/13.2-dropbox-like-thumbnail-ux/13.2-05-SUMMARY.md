## Decisions Made

- **`.indexing` callsites that were UX-meaningful were collapsed to `.sync`** rather than deleted (S3Enumerator x2, FileProviderExtension.materializeFolderItem). The user-visible "something is happening" signal is preserved by NotificationManager's existing active-operations counter — D-16's central premise.
- **`.indexing` callsites that were aggregator-only were deleted** (AppStatusManager `case .syncing, .indexing` arm, DS3DriveManager status mapper, AggregateStatus reducer arm, all view switches). These were transformations whose only purpose was to keep the dedicated state alive.
- **NotificationManager required no logic change.** PATTERNS.md's expectation of a `.indexing → .busy` collapse helper (~30 LoC) didn't match reality — the file's existing `activeOperations` counter already handles the collapse, and the only `.indexing` reference was a docstring. Documented this in the task commit.
