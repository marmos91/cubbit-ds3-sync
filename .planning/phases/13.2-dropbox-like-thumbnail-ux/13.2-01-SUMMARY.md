**2-slot FIFO actor with in-memory 3-strike poison set — cornerstone for Phase 13.2's cache-miss fallback lane in `fetchThumbnails`, replacing the dying Schema V4 `thumbnailFailCount` field with a process-lifetime in-memory counter.**

## Accomplishments

- **`ThumbnailFallbackLimiter` actor** with 2-slot FIFO acquire/release, cancellation-aware suspension, and post-resume `Task.isCancelled` guard that returns the slot before throwing.
- **In-memory 3-strike state** holding a `[String: Int]` strike counter and `Set<String>` poison set, both scoped to the actor and reset on extension restart (D-19, D-20, D-21). This is the runtime replacement for the SwiftData-backed `thumbnailFailCount` field that Plan 13.2-08 will drop in Schema V5.
- **9 unit tests** covering: below-cap acquire, blocking at cap, FIFO across two waiters, cancellation-removes-waiter, recordFailure-increments, third-strike-poisons, recordSuccess-resets, poisoned-key-idempotent-on-extra-failures, separate-keys-have-separate-counters. All green.
- **Dual-target inclusion** in `DS3Drive.xcodeproj`: source compiles into both `DS3DriveProvider` (production) and `DS3DriveProviderTests` (so tests can reach the type without `@testable import`), mirroring the existing `ThumbnailFetchLimiter` pattern.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] SwiftLint identifier_name violation in OrderRecorder helper**
- **Found during:** Task 1 (RED) commit pre-commit hook
- **Issue:** SwiftLint flagged `func record(_ s: String)` for parameter name `s` (single character) in the test helper actor `OrderRecorder`. The plan's literal text used `s`, but the project's SwiftLint config requires identifier names ≥ 2 characters.
- **Fix:** Renamed `s` → `value` in both the parameter declaration and the body of `OrderRecorder.record`. No semantic change.
- **Files modified:** `DS3DriveProviderTests/ThumbnailFallbackLimiterTests.swift`
- **Verification:** SwiftLint passed; commit succeeded.
- **Committed in:** `a1dc3af` (Task 1 commit, fixed before commit landed)

**2. [Rule 1 - Style] Test helper Task chaining replaced async-let in FIFO test**
- **Found during:** Task 1 (RED) initial draft authoring
- **Issue:** Plan's literal Swift used `async let a: Void = { ... }()` with a closure-call form. This form is awkward in Swift 6 (the closure-as-value with explicit `()` invocation triggers actor-isolation warnings on the in-line `try await`).
- **Fix:** Rewrote as named `Task { ... }` blocks (`taskA`, `taskB`) and awaited `.value` after the gating `release()`. Same observable FIFO contract; cleaner concurrency story.
- **Files modified:** `DS3DriveProviderTests/ThumbnailFallbackLimiterTests.swift`
- **Verification:** `testFIFOOrderPreservedAcrossWaiters` passed in 0.064s; recorded `["A", "B"]` ordering as expected.
- **Committed in:** `a1dc3af`
