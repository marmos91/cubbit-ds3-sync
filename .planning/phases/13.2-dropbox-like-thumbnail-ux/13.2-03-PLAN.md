<objective>
Add the post-PUT `signalEnumerator(for: parentContainer)` to the upload-hook detached Task. After a fresh upload writes both the original and the `.thumbnails/<key>.jpg`, this signal nudges Apple to re-enumerate the parent folder so the just-uploaded thumbnail is fetched and displayed without manual refresh.

Purpose: Symmetric with the fallback path (Plan 02). Both PUT paths — upload hook AND fallback render — call `signalEnumerator(parent)` after success (D-12). The user sees thumbnails appear after upload without restarting Finder or refreshing.

Output: `ThumbnailUploadHookContext` extended with `domain: NSFileProviderDomain`; the post-PUT block in `enqueueThumbnailUpload` calls `manager.signalEnumerator(for: parentId)` after successful `generateAndUpload`; existing `UploadHookTests` extended with assertion that the signal closure is invoked.

**Step 2: Add post-PUT signal inside `enqueueThumbnailUpload`'s detached Task.** Find the line where `try await uploader.generateAndUpload(...)` is called. Immediately after the PUT succeeds, add:

```swift
// Phase 13.2 D-12: signal the parent container so Apple re-enumerates
// the folder and the just-uploaded thumbnail is fetched on the next
// visit. Symmetric with the fallback path's post-PUT signal.
if let manager = NSFileProviderManager(for: ctx.domain) {
    let parentKey = S3PathUtils.parentKey(forKey: ctx.originalKey)
    let parentId: NSFileProviderItemIdentifier =
        parentKey.map(NSFileProviderItemIdentifier.init) ?? .rootContainer
    manager.signalEnumerator(for: parentId) { error in
        if let error {
            ctx.logger.error(
                "Upload-hook signal failed for \(parentId.rawValue, privacy: .public): \(error.localizedDescription, privacy: .public)"
            )
        }
    }
}
```

The `error.localizedDescription` is acceptable here because `signalEnumerator` returns a vanilla `NSError`, not a Soto error. The `describeSotoError` rule applies only to Soto errors. Document this in a comment.
