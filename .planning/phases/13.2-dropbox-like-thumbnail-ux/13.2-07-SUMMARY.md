# Phase 13.2 Plan 07: Delete Coordinator + Sweeper + Rollout + Warm-cache — Summary

Removed all remaining background-work scaffolding from the thumbnail subsystem: the `ThumbnailBackfillCoordinator` actor, the `OrphanSweeper` struct, the launch-time `ThumbnailRollout` driver (`runThumbnailRolloutIfNeeded`), and the BFS-era sentinel-purge cleanup block embedded in `warmCache`. With BFS already gone (Plan 06) and the reactive consume path live (Plan 02), these were pure overhead. The cold-folder UX bug from RESEARCH Finding 7 is now solved structurally — there is no global pass to wait for.

## What changed

- **Deleted** (6 files, 2 308 LoC):
  - `DS3Lib/Sources/DS3Lib/Thumbnails/ThumbnailBackfillCoordinator.swift` (323 LoC) — the sequential per-drive backfill engine: thermal/pause gates, 3-strike failure routing, render+PUT loop. No longer driven by anything after BFS deletion.
  - `DS3DriveProvider/OrphanSweeper.swift` (200 LoC) — listed `.thumbnails/` keys, diffed against BFS-enumerated original keys, deleted up to 50 orphans per pass with MetadataStore freshness backstop. With BFS gone there's no enumerated-key set to diff against; cascades become the sole orphan prevention (D-25).
  - `DS3DriveProvider/ThumbnailRollout.swift` (~85 LoC) — once-per-drive launch-time bucket inspect → settings persist. Wizard's `inspectThumbnailPrefix` (Phase 11) covers the same ground at drive-add time (D-09).
  - `DS3Lib/Tests/DS3LibTests/ThumbnailBackfillCoordinatorTests.swift` (457 LoC) — 11-test coverage suite for the coordinator (thermal gate, pause gate, strike rule, cancel-in-flight semantics).
  - `DS3DriveProviderTests/OrphanSweepTests.swift` (~415 LoC) — 9-test coverage suite for the sweeper (D-25/26/27/28 gates, list pagination cap, freshness backstop).
  - `DS3DriveProviderTests/ThumbnailRolloutTests.swift` (~390 LoC) — 8-test coverage for idempotency, error handling, settings persistence.
- **Modified**:
  - `FileProviderExtension+Lifecycle.swift` — deleted `runThumbnailRolloutIfNeeded` function + its MARK section; deleted the sentinel-purge block (~12 lines) inside `warmCache`'s detached Task. Cache warm-up itself (recursive S3 listing → MetadataStore upserts) is preserved verbatim.

None. The deletion shrinks the attack surface significantly:

- **T-removed-01** — Race between consume-fallback PUT and orphan sweeper: DELETED (sweeper gone).
