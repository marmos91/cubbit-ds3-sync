# Phase 13.2 Plan 02: fetchThumbnails Cache-Miss Fallback Fork Summary

Adds the cache-miss fallback fork to `fetchThumbnails` (lanes 2 + 3 of the Dropbox-like 3-lane model) so cold-folder browses immediately serve a rendered thumbnail and asynchronously warm the S3 cache for the next visit.

## Context

Phase 13.2 replaces the BFS-driven thumbnail subsystem with a reactive, Apple-API-driven 3-lane model:
1. **Cache hit** — `.thumbnails/<key>.jpg` from S3 (fast, ~50 KB)
2. **Cache-miss render** (this plan) — download original + render JPEG locally, return bytes immediately to Finder
3. **Background backfill PUT** (this plan) — fire-and-forget Task PUTs the rendered JPEG to S3 and signals the parent container

Plan 01 shipped `ThumbnailFallbackLimiter` (the 2-slot limiter + in-memory strike counter / poison-key set). Plan 02 wires the limiter into `fetchThumbnails` and implements the hybrid consume fork.

## Implementation Highlights

### `consumeThumbnailFallback` — free function in `+ThumbnailConsume.swift`

```swift
@Sendable
func consumeThumbnailFallback(
    identifier: NSFileProviderItemIdentifier,
    drive: DS3Drive,
    context: ThumbnailFallbackContext,
    perItemHandler: PerThumbnailCompletionHandler
) async
```

Sequence (each step is a hard precondition for the next):

1. **Poison check** (D-19, D-20) — `limiter.isPoisoned(key)` short-circuits with `(nil, nil)`.
2. **Pause gate** (D-24, THUMB-21) — `isPaused(drive.id)` short-circuits BEFORE acquiring a slot. No paused drive ever blocks the 2-slot pool.
3. **Acquire** a 2-slot fallback limiter slot. Cancellation maps to `NSUserCancelledError`.
4. **Download** original via the `download` closure. Throw → strike + `mapThumbnailFetchError` → return mapped NSFileProviderError.
5. **Render** via the `render` closure. nil → strike + `.noSuchItem`. Renderer's `mappedIfSafe` Data load (Phase 13.1 Finding 2 fix) keeps memory bounded.
6. **Lane 2** — `perItemHandler(identifier, jpegBytes, nil)` returns the rendered bytes to Finder immediately. `recordSuccess` resets the strike counter.
7. **Lane 3** (D-04, D-12) — `Task.detached(priority: .background)` PUTs the SAME bytes (single render) to `.thumbnails/<key>.jpg`, then on success calls `signalParentContainer(parentId)` so Apple re-enumerates and the next `fetchThumbnails` hits the warm cache. PUT failures are logged via `describeSotoError` and swallowed — the user already saw a thumbnail.

### Closure-based DI via `ThumbnailFallbackContext`

`consumeThumbnailFallback` takes a `ThumbnailFallbackContext` (Sendable struct) with five `@Sendable` closures (`download`, `render`, `putThumbnail`, `isPaused`, `signalParentContainer`) plus the limiter and logger. Production wires these to `S3Lib.downloadS3Item`, `ThumbnailRenderer().renderJPEG`, `s3Client.putThumbnail`, `SharedData.default().isDrivePaused`, and `manager.signalEnumerator(for:)`. Tests inject stubs.

This matches the existing `ThumbnailUploadHookContext` pattern and satisfies SwiftLint's `function_parameter_count` rule while keeping the function unit-testable without mocking the FileProviderExtension subclass.

### Cache-miss interception in `spawnCacheFirstThumbnailTask`

Rather than refactor `consumeThumbnail`'s signature (Plan 09 strips `markPending` later), the cache-first path now wraps the per-item callback with an interceptor that detects the unique cache-miss sentinel — `(nil, NSFileProviderError(.noSuchItem))` — and routes the identifier into `consumeThumbnailFallback`. Cache HIT bytes and real errors pass through unchanged.

`mapThumbnailFetchError` never returns `.noSuchItem`, so this is a clean discriminator.

### Sendable safety (Pitfall 1)

`consumeThumbnailFallback` is a free function. The detached PUT Task captures only sendable locals (`putFn`, `signalFn`, `bucket`, `thumbKey`, `jpegBytes`, `etagForPut`, `parentId`, `logger`) — never `self`. The FP extension subclass is `@unchecked Sendable` but capturing `self` from a detached Task remains a code smell flagged by reviewers, so the free-function pattern is preserved.

## Deviations from Plan

### Plan-vs-Reality Adjustments

**[Rule 3 — API correction] `putThumbnail` signature**
- **Found during:** Task 2 implementation
- **Issue:** Plan instructions say `s3Client.putThumbnail(bucket:key:jpegData:sourceETag:nil)`. Actual API in `DS3S3Client+Thumbnails.swift` is `putThumbnail(bucket:key:data:sourceETag:)` — `data:` not `jpegData:`, and `sourceETag` is non-optional `String`.
- **Fix:** Used `data:` and pass `sourceETag ?? ""` (empty string when the original GET didn't surface an ETag — matches existing upload-hook semantic for unknown-source thumbnails). The download path returns the source `S3Item.metadata.etag` so most cases will have a real value.
- **Files modified:** `DS3DriveProvider/FileProviderExtension+ThumbnailConsume.swift`
- **Commit:** `403cf0e`

**[Rule 3 — API correction] `S3PathUtils.parentKey` signature**
- **Found during:** Task 2 implementation
- **Issue:** Plan instructions show `parentKey(forKey:)`. Actual API takes `parentKey(forKey:drivePrefix:)`.
- **Fix:** Pass `drive.syncAnchor.prefix` as the `drivePrefix` argument.
- **Commit:** `403cf0e`

**[Rule 3 — API correction] `ThumbnailRenderer.renderJPEG` is non-throwing**
