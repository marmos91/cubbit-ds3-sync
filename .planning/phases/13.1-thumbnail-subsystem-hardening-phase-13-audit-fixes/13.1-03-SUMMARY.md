## Decisions Made

- Kept `describeSotoError` private to the cascade file. The codebase-wide log opacity sweep (D-06) is Plan 13.1-05's scope; an export would have invited file-modified overlap with that plan. Plan 13.1-05 may promote it later if the same helper is needed at other Soto-throws sites.
- Imported `SotoS3` directly in `CascadeRenameTests.swift` rather than building a fake `AWSErrorType`-conforming struct. `AWSErrorContext`'s `init` is internal, so a fake would have to use `context: nil` only — not a clean shape. SotoS3 was already linked transitively via `DS3Lib` so the import compiles in `DS3DriveProviderTests` without any project-file changes.
- Seeded the regression test's polling row to `.uploaded` (via a follow-up `setThumbnailStatus`) so the cascade's `.pending` write is the only signal the polling loop can detect. This caught a latent issue where Test 9 (`testRenameItemCopyFailureMarksNewKeyPending`) seeds with the schema default `.pending` and may complete before the cascade Task fires — a follow-up tightening could apply the same pattern there, but that is out of scope.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Polling loop in regression test exited before cascade Task ran**

- **Found during:** Task 1 (regression-test write-up + first run)
- **Issue:** The test seeded `metadataStore.upsertItem(s3Key: newOriginalKey, ...)` and then polled for `thumbnailStatus == .pending`. SyncedItem's schema default is `thumbnailStatus = ThumbnailStatus.pending.rawValue` (DS3Lib/Sources/DS3Lib/Metadata/SyncedItem.swift:328), so the polling loop exited on its first iteration BEFORE the cascade Task had run `s3Client.copyThumbnail`. Subsequent assertion `mock.copyObjectPairs.count == 1` failed because the copy had not yet been attempted at observation time. (Verified by debug-printing `copyPairs` immediately before the assertion: `DEBUG copyPairs=[]` while a millisecond later the cascade log line printed.)
- **Fix:** After upserting the seed row, transition its `thumbnailStatus` to `.uploaded` via `setThumbnailStatus(...)`. Now the polling loop only succeeds after the cascade's catch block executes `setThumbnailStatus(.pending)`, which guarantees `copyThumbnail` ran (the catch can only fire after the throw, which only happens after the mock appended to `copyObjectPairs`).
- **Files modified:** `DS3DriveProviderTests/CascadeRenameTests.swift`
- **Verification:** Ran the test — passed deterministically across two consecutive invocations.
- **Committed in:** `947e162` (part of Task 1 commit)
