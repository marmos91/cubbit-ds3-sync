## Decisions Made

- **Surgical fix over helper method.** The spike's Recommendation 2 (introduce `Progress.markFinishedTerminal(success:)` helper + `defer { ... }`) was rejected: the surgical line-per-catch insertions are clearer in code review and easier to spot in `git blame` than a deferred helper. The helper's defer-based safety net is already covered by the inner-layer `S3Lib+Transfers.swift` finalization (defense-in-depth at the throwing site).

- **Cancellation closures finalize explicitly.** Foundation's `Progress.cancel()` sets `isCancelled = true` and invokes the cancellation handler — but does NOT set `completedUnitCount = totalUnitCount`. For parent-folder aggregation in `fileproviderd`, the explicit finalization is required regardless of cancellation state. Both the existing `task.cancel()` AND the new explicit `progress.completedUnitCount = progress.totalUnitCount` are present in the cancellation closure (belt-and-braces).

- **Inner-layer finalization uses optional-chaining.** `S3Lib.getS3Item` and `S3Lib.downloadS3Item` accept `progress: Progress?`. The inner finalization uses `progress?.completedUnitCount = progress?.totalUnitCount ?? 0` so it's a no-op when `progress` is nil and explicit when it isn't. `getS3ItemRange` takes a non-optional `Progress` and uses the direct form.

- **Regression test isolates the contract from infrastructure.** Rather than build a full `FileProviderExtension` + mock `DS3S3Client` + in-memory `MetadataStore` test (which would test multiple things at once and slow down CI), the regression test verifies the lifecycle invariant directly: construct a `Progress`, run a closure that mirrors the catch-arm finalization, assert the observable state. If a future edit removes the finalization line from any catch arm, callers that hold the Progress lose the finalization signal and these tests fail deterministically.

- **Test for both `progress.completedUnitCount == progress.totalUnitCount` AND `progress.isFinished == true`.** `isFinished` is the higher-level Foundation observable that fileproviderd's parent-folder aggregator likely uses; pinning both makes the test more robust to internal Foundation changes.
