# Phase 13.1 Plan 05: Codebase-wide describeSotoError Sweep Summary

Introduced the canonical public `DS3S3Client.describeSotoError(_:)` helper and replaced `error.localizedDescription` with it at every Soto-throws catch site across `DS3DriveProvider/` and `DS3Lib/Sources/DS3Lib/`. Future operators see human-readable AWS error codes (e.g., `NoSuchKey: noSuchKey: The specified key does not exist.`) in logs instead of the Foundation-bridge artifact (`SotoS3.S3ErrorType error 1`).

## What Shipped

- **Public helper** in `DS3Lib/Sources/DS3Lib/DS3S3Client.swift`:
  ```swift
  public static func describeSotoError(_ error: Error) -> String {
      if let code = s3ErrorCode(from: error) {
          return "\(code): \(String(describing: error))"
      }
      return String(describing: error)
  }
  ```
  Co-located with the existing `s3ErrorCode(from:)` / `isNotFoundError(_:)` / `isRecoverableAuthError(_:)` Soto introspection helpers. Defeats Foundation's `Error`-bridge static-dispatch quirk: `(error as any Error).localizedDescription` on a Soto `AWSErrorType` yields the opaque "SotoS3.S3ErrorType error 1"; `String(describing: error)` dispatches through the concrete type's `CustomStringConvertible` (which `AWSErrorType` provides via its `description` requirement) and yields the readable form. When an AWS code is recoverable, prefixes it for grep-ability.

- **Three unit tests** in `DS3Lib/Tests/DS3LibTests/DescribeSotoErrorTests.swift`:
  1. `testDescribesNonAWSErrorWithoutPrefix` — NSError without AWS code → output equals `String(describing:)` with no prefix. Negative path lock.
  2. `testDescribesAWSErrorWithCodePrefix` — `S3ErrorType.noSuchKey` → output starts with `"NoSuchKey: "` and contains the readable case-name body. Positive path lock; also asserts the result is NOT the Foundation-bridge `"error 1"` artifact.
  3. `testDescribesDifferentAWSErrorCode` — `S3ErrorType.noSuchBucket` → output starts with `"NoSuchBucket: "`. Guards against accidental hard-coding of one error code.

- **Codebase-wide sweep** — 35 catch-site replacements across 16 files, all of the pattern `\(error.localizedDescription, privacy: .public)` → `\(DS3S3Client.describeSotoError(error), privacy: .public)`. Per-file site count:

## Key Decisions

1. **Canonical public helper, not file-local copies.** Plan 13.1-03 introduced a file-local private `describeSotoError` in `FileProviderExtension+ThumbnailCascade.swift` as a stop-gap; this plan promotes the same logic to a `public static` method on `DS3S3Client` so every future Soto-throws catch can reuse it without copy-paste. The cascade file's private helper remains intact per the plan's explicit instruction (acceptable known follow-up; do NOT delete in 13.1-05).

2. **Defensive helper application on ambiguous catches.** Per the plan's decision authority, when a catch site can wrap both Soto and Foundation errors (e.g., `Modify.swift:258` Restore from trash, `ThumbnailBackfillCoordinator.swift:235` temp-file alloc that the plan describes as "wraps Soto getObject" but is actually `temporaryFileURL` Foundation), the helper is still applied — its `String(describing:)` fallback handles non-Soto cases gracefully. This satisfies both the success_criteria zero-grep check on the listed files and avoids re-debating per-line which throws Soto and which doesn't.

3. **ThumbnailBackfillCoordinator scope expansion.** Plan body explicitly listed only line 235 in this file. Lines 264 (Soto `getObject`) and 314 (Soto `putThumbnail`) were not in the plan-body enumeration but are unambiguously Soto throws — applying the helper to them satisfies the success_criteria intent ("all Soto-throws catches") and pre-empts the same diagnostic opacity hitting the backfill path. Lines 202 and 217 (SwiftData transitions) and 251, 298 (cancellation-check Foundation throws) remain untouched per the explicit OUT-OF-SCOPE list.

4. **Excluded files verified untouched.** `OrphanSweeper.swift` (Plan 13.1-02 — still has 2 `error.localizedDescription` sites, owned there). `FileProviderExtension+ThumbnailCascade.swift` (Plan 13.1-03 — uses its own file-local private helper, has 0 `error.localizedDescription`). `DS3Authentication.swift`, `DS3DriveManager.swift`, `UpdateChecker.swift`, `SharedData+thumbnailSettings.swift`, `MetadataStore.swift`, `PendingUploadStore.swift`, `FileProviderExtension.swift`, `ThumbnailUploader.swift`, plus the FileProvider/SwiftData/Foundation-only sites in `BreadthFirstIndexer.swift` and `FileProviderExtension+Lifecycle.swift` are all out-of-scope per D-06 and remain unchanged.
