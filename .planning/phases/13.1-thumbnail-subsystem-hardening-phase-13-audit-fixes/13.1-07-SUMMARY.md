## Decisions Made

1. **Defer manual D-19 reproductions to user post-merge.** The plan body's `<task type="checkpoint:human-verify" gate="blocking">` requires a real macOS drive with thumbnails enabled. This worktree is non-interactive with no Finder/device access. The plan-level objective explicitly says these scenarios "CANNOT run in this autonomous worktree environment." Captured every step (build & run, file selection, paste/rename actions, log-capture commands, S3 verification commands, PASS/FAIL criteria) in 13.1-SHIP-GATE.md so the user can execute deterministically post-merge. Reproduction Results section left as `<PENDING>` placeholders for user to fill in.
2. **Do not modify STATE.md / ROADMAP.md.** Plan body's Task 3 explicitly says to update both files — but the orchestrator's parallel-execution contract (in this plan's `<parallel_execution>` block) forbids it. The intended STATE.md/ROADMAP.md diff is captured verbatim in 13.1-SHIP-GATE.md under "Wave-4 Summary" so the orchestrator can apply it after merge.
3. **Treat the two pre-existing `S3ItemTests` failures as expected.** Plan 13.1-03's SUMMARY and `deferred-items.md` both verify these failures pre-exist on the Phase 13.1 base. The plan's `acceptance_criteria` says "No test marked FAIL in the gate doc" — interpreted as no NEW failure caused by Phase 13.1 work. The ship-gate doc explicitly calls them out as documented pre-existing failures, satisfying the spirit of the criterion (no Phase 13.1 regression) while staying truthful about the test-suite state.
4. **Use `--no-verify --no-gpg-sign` for commits.** The `<parallel_execution>` block in the plan-execute prompt instructs this; the SSH signing agent is unresponsive in non-interactive environments. The orchestrator's git-history cleanup step will re-sign during merge.
