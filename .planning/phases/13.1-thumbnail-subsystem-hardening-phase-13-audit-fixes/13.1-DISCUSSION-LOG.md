## OrphanFix (Finding 4 fix strategy)

| Option | Description | Selected |
|--------|-------------|----------|
| Fix A — MetadataStore freshness backstop (Recommended) | Before deleting, check MetadataStore for SyncedItem keyed by originalKey. If row exists, skip delete. O(1) per candidate, uses existing data, matches subsystem persistence model. Add 7th OrphanSweepTest seeding SyncedItem for original NOT in enumeratedKeys. | ✓ |
| Fix B — HEAD original before deleting | Per-item S3 HEAD on implied original. Authoritative but expensive (up to 50 HEADs per worst-case sweep). D-28 originally rejected this; revisit? | |
| Fix A + Fix D defense-in-depth | Fix A as primary (MetadataStore) + skip first pass-tail sweep after any upload-hook fired in the pass. Slower to reclaim genuine orphans, belt-and-braces correctness. | |
| Fix C — Re-list originals AFTER BFS pass completion | Augment sweep to re-list originals at sweep time, not progressively. Doubles listing cost but eliminates the stale-snapshot window structurally. | |

**User's choice:** Fix A — MetadataStore freshness backstop.
**Notes:** Fix A is sufficient on its own; the upload-hook (Plan 13-07) writes the `SyncedItem` row synchronously alongside the original PUT, so the freshness backstop has the data it needs. swift-concurrency review expected during code review per the debug doc's specialist_hint.
