# Phase 13.1 Plan 04: Renderer Eager-Snapshot Fix Summary

Replaced `CGImageSourceCreateWithURL` with eager `Data(contentsOf:.mappedIfSafe)` + `CGImageSourceCreateWithData` in `ThumbnailRenderer.renderJPEG`, decoupling decode from URL lifetime and removing the concurrent-pressure nil-return failure mode reported in the Phase 13 audit.

## What Shipped

- **Renderer fix** in `DS3Lib/Sources/DS3Lib/Thumbnails/ThumbnailRenderer.swift`:
  - Eager-snapshot of file bytes via `Data(contentsOf: fileURL, options: .mappedIfSafe)` at the top of the `autoreleasepool`. Mapping is the kernel default when supported; eager copy on volumes that don't (e.g., FileProvider tempdir on some volumes).
  - `CGImageSourceCreateWithData(data as CFData, sourceOptions)` replaces the URL-backed source-create.
  - All other behavior preserved: `kCGImageSourceShouldCache: false` retained on source-create; `kCGImageSourceShouldCacheImmediately: true` retained on thumbnail-create; `kCGImageSourceCreateThumbnailWithTransform: true` retained for EXIF orientation; UTI allow-list (`allowedRasterUTIs`) still gates rejection of RAW/PDF/etc.
  - Public surface contract unchanged — `renderJPEG(from: URL) -> Data?`.

- **Three regression tests** in `DS3Lib/Tests/DS3LibTests/ThumbnailRendererTests.swift`:
  1. `testRenderJPEGSurvivesBulkPasteFanout` — 8 concurrent `renderJPEG` calls on `large-test.png` via `withTaskGroup`. Pins the 2026-04-27 15:14:35 audit symptom (6/8 nil under bulk-paste). Each task instantiates its own `ThumbnailRenderer` to satisfy strict-concurrency capture rules.
  2. `testRenderJPEGSucceedsOnRepeatedDecodesOfIdenticalBytes` — calls `renderJPEG` on `exif6-portrait.heic` twice with 200ms gap. Pins IMG_0015.HEIC re-paste symptom (15:06 success → 15:10 nil despite identical ETag).
  3. `testRenderJPEGSucceedsForCoordinatorOwnedTempFile` — copies `large-test.png` to a fresh `FileManager.default.temporaryDirectory` URL and renders. Pins the 15:19:03 backfill failure on the Cubbit retreat photo (renderer-owned temp file, not FileProvider tempdir).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Strict-concurrency capture in fanout test**
- **Found during:** Task 1 verification (`swift test --filter ThumbnailRendererTests`)
- **Issue:** Initial fanout test captured a `let renderer = ThumbnailRenderer(...)` into each `group.addTask` closure. `ThumbnailRenderer` is a value type but is not declared `Sendable`, so swift-test reported `[#SendingClosureRisksDataRace]: closure captures 'renderer' which is accessible to code in the current task` and the build failed.
- **Fix:** Capture only the `Sendable` `CGFloat` dimension and instantiate the renderer inside each task closure. Functionally identical (renderer is a stateless value type) but satisfies strict concurrency. Added a comment explaining the choice.
- **Files modified:** `DS3Lib/Tests/DS3LibTests/ThumbnailRendererTests.swift`
- **Commit:** `7f35929`

**2. [Rule 3 - Blocking] Renderer comment retained `CGImageSourceCreateWithURL` literal**
- **Found during:** Task 1 acceptance-criterion grep (`grep -c "CGImageSourceCreateWithURL"` returned 1).
- **Issue:** The Phase 13.1 explanatory comment originally read "URL-backed CGImageSourceCreateWithURL" — true, but the acceptance criterion explicitly requires zero occurrences in the file (the symbol must be eliminated everywhere, including comments, to prevent future grep-based audits from flagging it).
- **Fix:** Reworded comment to "previous lazy URL-backed image source". No semantic loss; criterion now satisfied.
- **Files modified:** `DS3Lib/Sources/DS3Lib/Thumbnails/ThumbnailRenderer.swift`
