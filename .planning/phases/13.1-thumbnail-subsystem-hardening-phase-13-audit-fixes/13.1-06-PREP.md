## Fix shape

Verbatim from spike `### Recommended fixes` (Recommendation 1, the surgical primary fix):

> **Recommendation 1 (smallest, most surgical — preferred):** add a guarded `progress.completedUnitCount = progress.totalUnitCount` to every error/cancellation arm in `fetchContents` (and the same pattern in Create/Modify/Delete/PartialContent).
>
> 1. `DS3DriveProvider/FileProviderExtension+Thumbnails.swift:119-140` — at the top of each `catch` arm, before `complete(nil, nil, ...)`, insert:
>    ```swift
>    progress.completedUnitCount = progress.totalUnitCount
>    ```
>    Three insertions: at line 120 entry (s3Error arm), at line 128 entry (CancellationError arm), at line 132 entry (generic catch).
>
> 2. `DS3DriveProvider/FileProviderExtension+Thumbnails.swift:144-147` — in the cancellation closure, also call `progress.cancel()` (the Foundation API that marks Progress as cancelled and completes its observers). Belt-and-braces: setting `progress.completedUnitCount = progress.totalUnitCount` in addition to `progress.cancel()` is safe and ensures parent aggregation releases regardless of which signal fileproviderd watches.
>
> 3. Mirror the same insertions in:
>    - `FileProviderExtension+Create.swift:140-178` (3 catch arms)
>    - `FileProviderExtension+Create.swift:255-285` (peer Create path)
>    - `FileProviderExtension+Modify.swift:180-216` (3 catch arms)
>    - `FileProviderExtension+Modify.swift:237-260` (restore-from-trash error arms)
>    - `FileProviderExtension+Delete.swift` (audit each catch arm; same guard)
>    - `FileProviderExtension+Thumbnails.swift:482-505` (`fetchPartialContents` error arms)
>    Use whichever local Progress variable is in scope (`progress`, `uploadProgress`, `putProgress`, etc.) and the matching `totalUnitCount` (often `numParts`).

### Before / after pattern (canonical)

**Before:**
```swift
} catch let s3Error as AWSErrorType {
    self.logger.error("Download failed for \(itemIdentifier.rawValue, privacy: .public) ...")
    await self.markItemAndParentAsError(...)
    await nm.sendDriveChangedNotificationWithDebounce(status: .error)
    complete(nil, nil, s3Error.toFileProviderError())
}
```

**After:**
```swift
} catch let s3Error as AWSErrorType {
    progress.completedUnitCount = progress.totalUnitCount  // <-- added: finalize Progress on terminal error path
    self.logger.error("Download failed for \(itemIdentifier.rawValue, privacy: .public) ...")
    await self.markItemAndParentAsError(...)
    await nm.sendDriveChangedNotificationWithDebounce(status: .error)
    complete(nil, nil, s3Error.toFileProviderError())
}
```

### Cancellation handler pattern

**Before:**
```swift
progress.cancellationHandler = {
    task.cancel()
    complete(nil, nil, NSError(domain: NSCocoaErrorDomain, code: NSUserCancelledError))
}
```

**After:**
```swift
progress.cancellationHandler = {
    task.cancel()
    progress.completedUnitCount = progress.totalUnitCount  // <-- belt-and-braces: also finalize on cancel
    complete(nil, nil, NSError(domain: NSCocoaErrorDomain, code: NSUserCancelledError))
}
```

Note: Foundation's `Progress.cancel()` sets `isCancelled = true` and invokes the cancellation handler — but the handler IS what we're modifying. Setting `completedUnitCount = totalUnitCount` directly is the explicit signal `fileproviderd` aggregates on for parent-folder UI release.

### Bug-epicenter pattern (S3Lib+Transfers.swift)

For the underlying `getS3Item` / `downloadS3Item` / `getS3ItemRange` catch blocks: these rethrow, so the catch arm in the calling FP method is what owns the Progress and runs the finalization. We add a single line `progress?.completedUnitCount = progress?.totalUnitCount ?? 0` (using optional-chaining since the parameter is `Progress?`) to the catch in `S3Lib+Transfers.swift` as defense-in-depth. This ensures even if a future caller forgets the catch-arm finalization, the inner layer has already finalized any partial Progress before rethrowing.

For non-optional Progress (`getS3ItemRange` takes `progress: Progress`):
```swift
} catch {
    progress.completedUnitCount = progress.totalUnitCount  // finalize on rethrow
    try? FileManager.default.removeItem(at: fileURL)
    throw error
}
```

For optional Progress (`getS3Item`, `downloadS3Item`):
```swift
} catch {
    progress?.completedUnitCount = progress?.totalUnitCount ?? 0  // finalize on rethrow (no-op if nil)
    try? FileManager.default.removeItem(at: fileURL)
    throw error
}
```

## Test strategy

**File:** `DS3DriveProviderTests/ProgressFinalizationOnErrorTests.swift` (new)

**Test functions:**

1. `testProgressFinalizedOnCatchArmAfterPartialProgress` — primary regression. Construct a `Progress(totalUnitCount: 100)` with `completedUnitCount = 42` (mid-fetch failure shape). Run a closure that mirrors the catch-arm finalization pattern. Assert `progress.completedUnitCount == progress.totalUnitCount` after the catch.

2. `testProgressFinalizedOnCatchArmFromZero` — instant-failure shape. Construct `Progress(totalUnitCount: 100)` with `completedUnitCount = 0`. Same finalization. Assert finalized.

3. `testProgressCancellationHandlerFinalization` — cancellation arm. Construct `Progress(totalUnitCount: 1)`, set the cancellation handler to mirror the new pattern (set `completedUnitCount = totalUnitCount` then complete). Assert finalized after `progress.cancel()`.

4. `testProgressIsFinishedAfterCatchArmCompletion` — observability shape. Verifies `progress.isFinished == true` (the observable that `fileproviderd` aggregates on for parent-folder UI release) after catch-arm finalization.

**Assertion shape:** `XCTAssertEqual(progress.completedUnitCount, progress.totalUnitCount)` AND `XCTAssertTrue(progress.isFinished)` after the catch arm runs. The fix's contract is exactly this: every terminal path finalizes Progress.

These tests pin the **invariant** the fix establishes (Progress finalization on catch). They do not depend on a real `FileProviderExtension`, `DS3S3Client`, or network — they test the lifecycle invariant in isolation, which is the most robust form for a "missing line in catch arm" regression. If a future edit removes the new lines, the test FAILS deterministically because the invariant is lost.

The test isolates the contract from infrastructure (no XCTestExpectation gymnastics, no actor scheduling, no mock S3 client) — `Progress` is a Foundation primitive whose lifecycle observably changes when `completedUnitCount` is set.
