## Spike output — root cause summary

**Bug epicenter:** `DS3DriveProvider/S3Lib+Transfers.swift:90-92` — `progress.completedUnitCount = progress.totalUnitCount` is set inside the `do` block of `downloadS3Item`. The catch at line 106 rethrows without finalizing the Progress.

**Bug propagation:** `DS3DriveProvider/FileProviderExtension+Thumbnails.swift:119-141` — three catch arms (`s3Error as AWSErrorType`, `is CancellationError`, generic) call `complete(nil, nil, error)` but never set `progress.completedUnitCount`. Same systemic pattern mirrored in `+Create.swift`, `+Modify.swift`, `+Delete.swift`, and `fetchPartialContents`.

**Why parent stays in progress:** Finder/`fileproviderd` aggregates child `NSProgress` lifetimes onto the parent folder's UI activity indicator. While at least one child Progress remains "active" (`completedUnitCount < totalUnitCount` AND not cancelled), the parent shows the spinner. A failed download leaves the Progress at the partial value the last `transferProgress` callback wrote, so the system treats it as still in progress indefinitely — even though the completion handler fired with an error long ago.

**Why decorations weren't enough:** `markItemAndParentAsError` (`FileProviderExtension.swift:319-335`) correctly stamps the parent's `syncStatus = .error` in MetadataStore, so the *error badge* propagates to the parent. But decorations and Progress are two independent dimensions in the FileProvider contract. Decorations show as badges; the spinner is system-rendered activity over the icon driven by NSProgress aggregation. The existing wiring addresses only the badge layer.

**Recommended fix shape:** add `progress.completedUnitCount = progress.totalUnitCount` (and `progress.cancel()` in the cancellation closure) at the top of every catch arm in fetchContents and its peers across the four extension files. Roughly 7 catch-arm insertions plus a regression test that mocks `getObject` to throw and asserts the returned Progress is finalized after the completion handler fires. ~50–80 LoC total. specialist_hint: fileprovider.
